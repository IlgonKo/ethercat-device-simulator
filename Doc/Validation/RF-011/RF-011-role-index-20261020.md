# RF-011 — OD role 조회 최적화 및 2축/4축 재검증 (2026-10-20)

- 문서 유형: **검증 기록**
- 현재 RF 상태: [상위 RF 문서 참조](../../RF/RF-011-device-configuration.md)

## 구현

- simulator/od_role_index.py에서 각 OD 인스턴스에 role→정의 목록 인덱스를 구성한다. 모델 생성 직후 설치하고 초기 인덱스를 만든다. 클래스 전체나 외부 Motion Server 소스는 수정하지 않는다.
- 값은 캐시하지 않는다. read_role/write_role은 현재 OD 값을 읽고 쓴다. 동일 role의 누락·중복 KeyError와 개수를 유지한다.
- define/overlay 호출 후 인덱스를 무효화하고 다음 조회에서 재구성한다. 실패한 정의 변경도 무효화한다. 정의 변경은 이 API를 사용해야 하며 entries를 직접 변경하는 외부 코드는 지원 계약이 아니다.
- 축별 OD·인덱스 독립성을 유지한다. Unix socket 순차 요청, PDO 매핑, 모델 운동 동작, timeout과 C++ 바이너리는 변경하지 않았다.
- 외부 모델 패키지 자체가 아닌 Simulator 인스턴스 어댑터로 구현했다. 향후 모델 패키지 통합 시 이 경계를 검토한다.

## 시험 조건

기존 실제 축 1개 + 실제 IO 1개 + 가상축 2/4개. Windows Motion Server, Linux enp1s0, 8 ms, DC off, PP Enable/정지 상태. 가상 4축은 linear 2개 + rotary 2개다. 기존 Master 시작 초기화/Enable는 실행하며 별도 이동·저장 명령은 보내지 않았다. 사용자 정지 확인 후 시험을 시작했고 종료 후 테스트 Master/Simulator를 정상 종료했다.

build/timing/cmmt_simulator 및 build/model-source-da0b0a3를 그대로 사용했다. Motion Server 소스·사용자 .env·Linux 사용자의 2축 설정은 유지했다. config/timing-2-axes.json, timing-4-axes.json을 명시했다.

Simulator/Python은 시작 10초에 걸치는 집계 창을 제외하고 표본 수 가중 평균을 사용한다. WKC는 Master 1초 상태 표본이며 모든 8 ms 주기의 무손실 증명은 아니다. PDO 처리 시간은 응답 후 모델 처리까지 포함하는 userspace busy 구간이며 선로 왕복 지연이 아니다.

## 오프라인 동일 환경 비교

물리 시험 종료 후 scripts/linux/benchmark-role-index.py를 실행했다. 동일 Linux 모델 소스의 PP 정지 상태에서 2,000회 model_update를 실행한다. 원본 조회와 인덱스 조회를 각각 실행하며 NIC를 열지 않는다.

- OD 7,400개, 원본 평균 1.149800 ms → 인덱스 평균 0.007167 ms (약 160배). 이 값은 소켓·PDO 변환·온라인 계측을 제외하므로 위 물리 시험의 모델 시간과 동일 범위가 아니다.
- 최종 전체 OD 값 동일. 외부 모델 소스 해시 동일.
- 명령: `python3 scripts/linux/benchmark-role-index.py --model-root build/model-source-da0b0a3 --output build/timing-bench/role-index-offline-20261020.json`

## 회귀 및 남은 범위

Windows Python 33개, Linux 관련 Python 30개 통과. 누락/중복 role, 재정의, overlay 생성/변경/실패, 현재 값 읽기, 반복 조회 시 전체 검색 없음, 축 독립성, 최적화 on/off PDO·파라미터 일치, 기존 4축 모드 및 영구 저장 검증을 포함한다. 테스트가 사용자 config/four-axes.json 수정에 영향받지 않도록 tests/fixtures/four-axes.json으로 분리했다.

이번 결과는 PP 정지 상태의 120초 물리 재검증이다. 장시간 운전, 물리 4축 동시 이동/모드 변경 부하와 RF-011의 나머지 완료 기준은 남아 있다. RF-011 전체를 완료 처리하지 않는다. 묶음 IPC는 미적용이며 이번 결과를 기준으로 필요성을 다시 판단한다.

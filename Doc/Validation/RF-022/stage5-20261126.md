## 벤치 및 수행 범위

Windows Motion Server/PySOEM → 실제 축·실제 IO → Linux Soft ESC를 케이블로 연결한 기존 8-Slave 벤치를 사용했다. 기대 WKC 24, Motion Server 주기 4 ms다. Simulator-local 0~3은 가상 축, 4~5는 CPX이며 Master axis 1~4가 가상 축이다. Master axis 0은 실제 축이다.

기본 구성은 F-KR 직선 2축 + Copley 2축 + CPX 2개/실린더 2개다. 추가 시험은 별도 `four.env`, `rf022-test-axis-*` 이름과 `state-four` 저장소로 F-KR 직선 2축 + 회전 2축을 구성했다. 운영 .env와 장치 정체성은 변경하지 않았다. 실제 축에는 이동/Homing 명령을 보내지 않았고 정지/Disable을 확인했다. Master 재시작 중 Enable은 기존 초기화 동작이며, 종료 시 전체 축을 명시적으로 Disable했다.

4축 F-KR 상세 운전은 축별 순차 시험이다. 동시 PP/실린더 시험은 기본 F-KR 2축+Copley 2축 구성에서 수행했다. 회전축 물리 벤치의 PP 범위는 ±5° 및 정지 시험용 50° 목표이며 200° 누적 동등성은 1~4단계 실제 FMU 오프라인 근거다. 기존 CSP는 실제 FMU와 Python의 동일 입력 비교 근거이며 이번 물리 벤치에서 별도로 반복하지 않았다. 이 구분을 다축 전체 동작 조합의 전수 검증으로 확대하지 않는다.

Host 장애 중 Fault Reset API 성공은 명령 처리 완료이며 장치 Fault 해제 성공을 뜻하지 않는다. 실제 Statusword Fault 유지로 확인했다. FMI 내부 오류/비정상 출력 및 core drive Fault의 세부 경계는 1~4단계 자동 시험 근거를 재사용하며, 이번 물리 시험에서 FMU에 새 오류 주입 인터페이스를 추가하지 않았다.

## 처리 시간 관측

같은 기본 topology/basic Master 4 ms 주기의 이전 Python 모델 정지 구간 약 26초와 새 FMU 정지 구간 약 18초를 비교했다. 아래 `model` 시간은 순수 C++ 계산만이 아니라 어댑터의 OD↔FMI 변환·호출을 포함한다. 평균은 표본 수 가중 평균이다.

| 지표 | Python 이전 이미지 | FMU 새 이미지 | F-KR 4축 시험 구간 |
| --- | --- | --- | --- |
| F-KR axis 0 model 평균 | 0.0149 ms | 0.1127 ms | 0.1157 ms |
| PDO frame 처리 평균 | 0.0878 ms | 0.0891 ms | 0.0892 ms |
| PDO frame 처리 최대 | 0.2800 ms | 0.2361 ms | 0.2649 ms |
| axis 0 비동기 IPC 완료 평균 | 1.1149 ms | 1.1133 ms | 1.1083 ms |

FMU 경계 호출 때문에 F-KR 어댑터 처리 시간이 증가했다. 따라서 C++ 이식이 전체 계산 성능 개선을 의미한다고 결론 내리지 않는다. 비동기 Slave 구조에서 이번 시험의 PDO 처리 및 WKC는 정상으로 관측됐다. 정상 운전 timing 로그의 ipc_failures는 0이다. 의도적으로 주입한 Host 장애 구간은 이 정상 운전 집계와 분리했다.

4축 로그의 전체 frame_busy 최대 15.272 ms는 초기화가 포함된 구간에서 관측됐고 같은 window의 PDO 최대는 0.136 ms였다. 위 표는 별도 pdo_frame_busy 지표이며 초기화 프레임과 혼동하지 않는다. 4축 IPC 완료 최대는 약 4.152 ms다. 짧은 표본·다른 운전 구간 비교이므로 최악 지연·모든 프레임 무손실·RT 성능을 보장하지 않는다.

## 복원 및 현재 상태

- 새 이미지로 기본 F-KR 2축/Copley 2축/CPX 2개 구성을 실행 중이며 컨테이너 healthy.
- Motion Server 기존 basic 모드·BUS·실행 환경 복원. 서버 소스 수정 없음.
- 운영 .env 바이트 동일. 네 축 파라미터 파일은 시험 전과 바이트 동일.
- PDO 매핑 identity/내용 동일. Master 재연결에 따라 revision은 24→26으로 증가했고 checksum도 갱신됐다. 매핑 파일까지 바이트 동일이라고 주장하지 않는다.
- 모든 축 속도 0, Disable, Fault 없음. 버스 normal/WKC 24/24, 조작권 owner=null.
- 가상 IO의 DO/AO는 시험 전 값과 일치. F-KR 두 축 새 이동 완료 후 위치 0. 실축은 위치를 유지했으며 위치 정확도 시험은 아니다.
- 시험용 임시 이름/저장소와 증거는 build/diagnostics 아래 보존하고 운영 설정에서 선택하지 않는다.

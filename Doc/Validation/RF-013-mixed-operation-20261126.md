## 구성과 시험 절차

Windows Motion Server의 기존 PySOEM 세션과 Linux Docker Soft ESC를 그대로 사용했다. 실제 CMMT 1축·실제 CPX 1 station 뒤에 가상 F-KR 2축·Copley 2축·CPX 2 station이 연결되어 총 Slave 8개, 논리 축 5개, 기대 WKC 24다. 가상 CPX io1/io2는 Master Slave 6/7이며 각각 DI8·DO8·AIO4/4 구성이다.

사용자가 가상축 PP·Enable·F-KR 원점 참조 상태를 수동 준비했다. 조작권이 비어 있는 것을 확인하고 **단일 TCP 클라이언트가 조작권을 확보하여 축 명령과 IO 출력을 함께 처리**했다. 별도 Panel에서 동시에 IO를 조작하지 않았다. 원점복귀·버스 재초기화·컨테이너 재시작 없이 진행했다.

- 가상 Axis 1~4를 기존 위치에서 ±5mm, 속도 10mm/s로 왕복했다. 축별 위치 범위: A1 3.112~8.112mm, A2 -5~0mm, A3 5~10mm, A4 -10~-5mm.
- 실린더 2개도 같은 구간에서 전진/후진시켰다. 방향 전환 시 이전 방향 DO를 OFF하고 새 방향 DO를 ON했다. 각 모델의 DO/DI는 기존 io1/io2 분산 binding을 그대로 사용했다.
- 30회 동작 전환, 축별·실린더별 15회 왕복을 수행했다. 매 전환에서 축 위치 오차 ≤0.01mm·속도 ≤0.01mm/s와 두 실린더의 기대 DI 조합이 연속 3개 표본에서 일치하는지 확인했다. 전환 간격은 약 2초이며 개별 판정 제한시간은 4초다. 최장 판정 시간은 0.669초였다.
- 실축 A0와 실제 IO에는 이동/출력 변경 명령을 보내지 않았다. 실축 관측 위치는 147.841~147.842mm다. 조작권 해제 시 Motion Server의 공통 Stop 절차는 실행되며 실제 축은 이미 정지 상태였다.
- 아날로그 출력 변경·물리 AO→FMU→AI 시험은 이번에도 수행하지 않았다. 기존 생략 결정을 유지한다.

## 종료·복원

가상축은 시험 시작 위치로 돌아왔으며 마지막 비교 오차는 4축 모두 0이다. 축 profile 설정은 시작 전 값과 동일하고 모든 축의 속도는 0이다. 가상축 Enable 상태는 유지했다. 두 실린더 센서 상태와 두 station의 DO/AO 출력은 시작 전과 일치한다. 조작권은 해제했고 최종 버스/서버 상태는 정상, WKC 24/24다. cleanup 오류는 없었다. 파라미터 영구 저장 명령과 state 파일 변경은 수행하지 않았다.

## 사전 시도와 검증 범위

사용자가 상태를 준비하기 전 자동 시도에서는 절대이동과 상대이동 API가 OPERATION_FAILED로 거부됐다. 혼합 동작 합격으로 계산하지 않았다. 당시 거부 응답에 세부 원인이 없어 원인을 단정하지 않는다. F-KR 원점 참조 미완료 상태는 확인했지만 이것만으로 상대이동 거부 원인까지 설명하지 않는다. Copley 축에는 일부 이동이 반영됐으므로 실패 응답이 모든 축 무동작을 보장한다고 보지 않는다. 성공 시험은 사용자가 준비한 위치를 새 시작점으로 기록했다.

사용자가 Copley Homing을 시도했을 때의 PP-only 어댑터 Fault는 이번 성공 구간 이전이며, 성공 구간에는 발생하지 않았다. Copley는 원점 참조 완료 비트를 제공하고 실제 Homing 모드 실행은 지원하지 않는 기존 범위를 유지한다.

## 증거와 남은 작업

원시 결과와 재현용 시험 스크립트는 Linux `build/diagnostics/rf013-mixed-20261126/`에 보관한다. 성공 기록은 `manual-ready-run/{result,samples,analysis}.json`, `responses.jsonl`, `feedback.jsonl`, `docker.log`다. `absolute-precheck/`는 사전 실패 기록이며 성공 기록과 분리했다. build 산출물은 Git 추적 대상이 아니다.

현재 혼합 구성의 정상 운전·WKC·시간·주기 기록을 확보했다. Host 정지/종료·응답 지연과 Docker 재시작/재연결 복구, CPX 모듈 재구성·재검색은 수행하지 않았으며 RF-013 잔여로 유지한다.

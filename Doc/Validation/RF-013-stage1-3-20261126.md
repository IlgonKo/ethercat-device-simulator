# RF-013 1~3단계 구현·검증 — 2026-11-26

- 결과: **1~3단계 구현 및 단계별 검증 완료**, RF-013 전체는 진행 중.
- 기준: Linux Soft ESC 작업 공간. 실제 실린더/아날로그 지연 FMU 연결·최종 통합은 4~5단계.
- 제품 이미지: `ethercat-device-simulator:rf013`, image config `sha256:54e7f220ae9f0a722012598594179e729307008ffc34b5144b2152200a8bb965`.
- Motion Server 소스/설정 및 기존 축 영구 파라미터는 수정하지 않았다. 기존 운영 이미지를 덮어쓰지 않고 별도 이미지로 시험했다.

기능 모델의 IO 실행부는 동작 모델을 직접 대신하지 않는다. 어댑터 생성 경계는 `initial_outputs()`, `step(inputs, time, dt)`, `close()`다. 시험에서는 테스트 코드의 주입형 어댑터를 사용한다. 제품의 `pneumatic_double_acting`/`analog_delay` FMU 어댑터가 아직 없으므로 모델을 실제 `.env`에 선언하면 **stage 4 required**로 시작을 거부한다. 임시 echo를 제품 모델로 등록하거나 실린더 FMU 검증 완료로 간주하지 않았다.

## 자동 검증

- Python unit 77개: 통과(기존 선택적 실제 FMU 시험 1개 skip). Docker에서는 별도 Copley FMU 통합 시험을 실제 Linux FMU로 수행.
- CTest 기존 6개 통과: 다중 Slave routing, 비동기 Host 장애, 축 매핑/저장/저장 실패 경계 포함.
- `run_remote_io.py`: KickCAT 실제 ESI parser·OD·메일박스·ESC로 2 station 검증. Identity, F030/F050, 개별 읽기, 모든 매핑 쓰기 거부, 정확한 Abort 명령/코드, CA·미지원 AP/save/history 거부, 잘못된 SM 크기 거부 후 복구, SAFE-OP/OP, bit PDO·AIO 공급 비트·후속 offset, WKC 확인.
- 같은 시험의 Unix 소켓 경로: 실제 ModelFleet/IO scheduler와 별도 테스트 어댑터 2개를 연결해 station 양방향 분산 binding·signed raw 전달 확인.
- 실행부 경계: 입력 둘 중 하나 누락 시 계산 없음, 두 DO가 ON이어도 그대로 전달, 계산 중 전체 입력 스냅샷 고정, 모델별 시간 8ms, 프레임 수와 계산 수 분리, 입력 station 상실 시 정지 및 모든 입력 station의 새 샘플 이후 재개, 진행 중 한 단계 정상 결과 수락, 출력 전용 station 상실 시 계산 지속.
- 지연/오류: 12ms 계산에도 dt는 8ms, 중복 실행/따라잡기 없음, 모델 출력 범위 오류 시 해당 모델 마지막 값 유지 및 정상 모델 지속. 제한시간 초과는 Host 전체 latch·늦은 결과 폐기. 모델 오류가 CPX 오류 OD에 투영되지 않음.
- 기존 F-KR/Copley 4축 `run_dynamic_mapping.py --motion` 및 `run_remap_ipc.py` 8개 장애/지연/이전 응답 시나리오 통과. Docker 빌드에서도 저장 시작/복원과 축 회귀 수행.
- Linux Motion Server 기존 CPX catalog/mapping validator를 읽기 전용으로 실행: 동일 모듈 구성의 (Rx,Tx) 크기 (11,9), (10,9) 및 개별 mapping word 일치.

## 물리 케이블 시험

Windows PySOEM 1.1.13 → 실제 CMMT → 실제 CPX → Linux 가상 CPX 2대. Windows NIC는 `NPF_{906A65C9-C606-4B1F-8384-2625829A4D18}`, Linux는 `enp1s0`. 실제 장비는 PRE-OP에 두었으며 Enable/이동 명령을 보내지 않았다. 가상 CPX만 OP로 전환했다.

| 시험 | 결과 |
| --- | --- |
| 최초 이미지 정상 세션 | 5초, 566회, 모두 WKC 6/6 |
| 최초 이미지 Model Host SIGKILL 이후 | 3초, 340회, 모두 WKC 6/6 |
| 최종 이미지 정상 세션 | 5초, 570회, 모두 WKC 6/6 |
| 최종 이미지 Model Host SIGKILL 이후 | 3초, 340회, 모두 WKC 6/6 |

- bus index 2/3에서 vendor 29, product 8086609, revision 2를 검색했다. 실제 CPX revision 4와 별개다.
- io0 DI8/DO8/AIO4/4/DO8: Rx 11 / Tx 9 byte. io1 DO8/DI8/AIO4/4: Rx 10 / Tx 9 byte.
- F050 확인 → F030 ident/count 동일값 쓰기 → 매핑 쓰기/27F1 거부 → config_map → OP → PDO 교환 → AO OD 읽기로 -32768/-1/0/32767 확인.
- 공급 비트 0/1을 교대로 전송하고 후속 DO offset을 유지했다. 미연결 DI/AI는 0이며 자동 loopback이 없다.
- Host 종료 이후에도 Slave 생존·SDO/OP/PDO 유지, 1001 및 6102 정상값 유지. supervisor는 model-failed, Slave 내부 진단은 MODEL_HOST_DISCONNECTED로 기록됐다.
- WKC 6은 OP인 가상 station 2개의 output/input 기여 3×2다. 전체 혼합 버스를 모두 OP로 운전한 WKC나 과거 18과 비교하지 않는다.
- master sleep 요청은 8ms이며 Windows에서 hard realtime 주기를 보장하거나 측정한 시험이 아니다. 동작 모델 8ms 계약은 별도 실행부 시험이다.
- 재현 스크립트: `tests/integration/probe_cpx_physical.py`. idle master NIC 및 2 station fixture를 명시적으로 준비해야 한다. 일반 운영 세션에 자동 실행하지 않는다.

시험 후 임시 `softesc-rf013-bench` 컨테이너는 제거했고 기존 `ethercat-device-simulator` 컨테이너를 재시작했다. 원래 `.env`·축 state·이미지 태그를 유지했다. Motion Server는 시험 시작 시 실행 중이 아니었으므로 자동 시작하지 않았다. 시험 master는 버스를 PRE-OP로 두고 종료했다. 사용자 다음 운전 시 버스 재연결/초기화가 필요하다.

## 남은 범위

- 4단계: 실제 FMU 초기화 전 설정, 실린더 어댑터, 지연 FMU 제작과 시간 지연 검증. 현재 시험용 identity adapter는 순수 지연 FMU의 완료 근거가 아니다.
- 5단계: 실제 FMU 4개와 2 station·축 혼합 물리 운전, 모델 초기 상태/재시작/일시정지 상태의 통합 확인.
- 전체 MDP/모든 CPX 모듈 적합성, IO-Link·모듈 설정·진단 PDO/이력/Emergency는 범위 밖이다. F000은 지원표에 명시한 최소 하위항목만 제공한다.

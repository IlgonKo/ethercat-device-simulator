# Soft ESC v1.0.0

- Release date: 2026-11-26 (Asia/Seoul)
- Status: **Released baseline — TD maintenance only until DT Demo completion**
- Git tag: `v1.0.0`; package version: `1.0.0`
- Platform: Linux x86-64 / Docker Engine + Compose
- Runtime baseline: RF-022 implementation commit `f90cc71a583f405129efad50359448645103a819`.
  The release commit adds version metadata, current documentation and the feature-freeze policy; it does not change runtime behaviour.

## Included functionality

- KickCAT-based EtherCAT slave simulation and physical/virtual mixed-bus operation.
- CiA402 Drive profile with F-KR CMMT linear/rotary FMI 3.0 Co-Simulation FMUs and the existing Copley adapter.
- PP/PV/Jog/virtual Homing/stop/reset behaviour within the model-specific support contract.
- CPX-AP-I-EC Modular Remote I/O, DI/DO/AI/AO and cylinder/analog-delay model bindings.
- Independent .env configuration, named axes, persistent device parameters and accepted axis PDO mappings.
- PRE-OP axis remapping through individual SDO access; CPX uses fixed configuration-derived PDOs.
- Model-host fault isolation, internal diagnostics, axis Fault Reset and manual Docker recovery.
- Docker multi-stage source build and offline export/verification/restore/rebuild tools.

## Selecting the release image

After loading the release image on the target machine, use the existing fixed-name scripts:

```bash
docker tag ethercat-device-simulator:1.0.0 ethercat-device-simulator:dev
bash scripts/docker/start.sh
```

Stop motion/disconnect the master and back up configuration/state before switching an existing installation. Reconnect/initialize the master afterwards. `--build` is unnecessary when using the prepared image. Source-build and offline prerequisites are documented in the deployment guide; native host compiler installation is not required for Docker builds.

## Known limits

- Copley Moving B8 and Halt differ from F-KR; Copley PV/Jog/Homing support was not added.
- No Complete Access or duplicate OD mapping. CPX mapping is read-only.
- No IO-Link, CPX diagnostic PDO/history/Emergency, or propagation of model errors as CPX device faults.
- Analog manual/physical FMU end-to-end acceptance was omitted by agreement; offline tests passed.
- No new rotary modulo/shortest-path/CSP coordination, motor electrical/torque/load model, or standard conformance/RT certification.
- Missing or incompatible saved data/artifacts are not silently migrated or replaced by another model.
- Model-host faults require manual restart; public model recovery/position acceptance APIs are not included.

## Maintenance through DT Demo

Only TD fixes for bugs or deficiencies in already implemented features may proceed. New RF feature implementation is frozen until explicit review after DT Demo completion. A feature expansion must not be relabelled as a TD to bypass this boundary.

RF-021 is deferred until after DT Demo. RF-019/020 are outside the v1.0/DT Demo scope and remain long-term reference items. RF-012's existing-feature deployment acceptance is deferred to Demo equipment setup. RF-006~009 remain external-system responsibilities. Patch releases may carry validated TD fixes; preserve the v1.0.0 tag and artifacts.

See [ADR-011](../Design/ADR-011-v1-maintenance-policy.md) and the [project plan](../project-plan.md).

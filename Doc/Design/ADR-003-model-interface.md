# ADR-003 — 동작 모델 연결과 실행 경계

- 결정 상태: **채택** (현행 범위 기준; 본문의 보류·과거 제안은 구분)
- 결정일: 2026-09-15
- 갱신일: 2026-11-25
- 구현 상태: 자체 F-KR CMMT·Copley FMI3 Co-Simulation 및 Host 장애 격리 검증 완료. Modular Remote I/O·모델 연결 확장은 RF-013 진행 대상.
- 관련: [제품 구조](ADR-001-system-architecture.md), [프로파일/어댑터](ADR-007-cia402-profile-adapters.md)

## 기능 모델과 동작 모델

기능 모델은 장치 프로파일·모델별 어댑터·동작 모델을 포함한다. 동작 모델은 장치 또는 연결 대상의 동작을 계산한다. 자체 코드·FMU·기타 형식은 모델을 제공하는 방식이며 장치 프로파일과 일대일로 고정하지 않는다.

CiA402 Drive와 EtherCAT Modular Device Profile 기반 Remote I/O를 모두 제품 범위로 둔다. Remote I/O의 모듈/채널 데이터 정의와 Loader 등 연결 대상의 동작 계산은 분리한다. 특정 DT·Master 애플리케이션을 모델 실행에 요구하지 않는다.

## 실행 구조

```text
EtherCAT Slave (C++ / KickCAT)
   ↕ Unix Socket IPC: OD 정의·값 접근·동작 계산 요청/결과
Functional Model Host (현재 Python)
   ├─ 장치 프로파일·독립 장치 값/상태
   ├─ 어댑터: 변수·타입·단위·기능 의미 연결
   └─ 자체 동작 모델 또는 FMU 라이브러리
```

Slave와 Host는 별도 프로세스다. 어댑터와 FMU는 Host에서 호출하며 현재 FMU마다 별도 프로세스/IPC를 만들지 않는다. 한 Host의 여러 축은 독립 모델 인스턴스지만 Host 충돌의 영향은 공유한다. IO의 모듈/채널과 모델 인스턴스 연결 단위는 RF-013에서 확정한다.

동일 장치의 같은 동작을 자체 모델과 FMU에서 동시에 계산하지 않는다. 모델이 이미 상태 머신/제어기를 제공하면 어댑터에서 중복 구현하지 않는다. 모델에 없는 프로파일 기능은 어댑터의 지원/미지원 계약으로 명시한다.

## OD·PDO·저장

장치당 논리 OD 하나를 유지한다. 프로파일은 자료형·접근 권한·매핑 가능 여부·명령 의미를 정의한다. 장치 값과 동작 모델 적용 시점은 어댑터/Host 계약을 따르고 별도 값 사본을 독립 원본처럼 취급하지 않는다.

PDO mapping/assignment·검증·활성화·저장은 Slave 책임이다. 모델 IPC는 매핑 정보를 전달하지 않으며 기능 모델이 매핑을 활성화하지 않는다. 동작 파라미터는 기능 모델의 저장소를 사용한다. [RF-014](../RF/RF-014-dynamic-pdo-mapping.md)와 [RF-010](../RF/RF-010-parameter-persistence.md)의 경계를 유지한다.

SDO 쓰기는 모델/어댑터의 검증·적용 결과를 반영한다. 거부한 요청을 성공으로 응답하거나 모델 미적용 값을 적용된 것처럼 반환하지 않는다. 지원 요청과 Abort의 구체적 범위는 프로파일별로 명세한다.

## 모델 형식과 지원 범위

- 현재 자체 모델: `f_kr_cmmt`, CiA402 Drive 연결.
- 현재 FMU: `copley_drive_sim`, FMI3 Co-Simulation을 FMPy 기반 실행기로 호출. Copley 변수/단위/지원 기능은 별도 어댑터와 모델 정의가 담당한다.
- 기타 FMU/형식: 확장 가능한 구조를 제품 범위로 두되 로더·변수/시간·플랫폼·기능 계약과 시험 없이 자동 호환을 주장하지 않는다. FMI Model Exchange를 현재 지원 범위에 추가하지 않는다.
- Remote I/O: Modular Device Profile과 모델 연결은 RF-013에서 구현한다. Loader는 자체 동작 모델을 사용할 수 있으며 FMU를 필수로 요구하지 않는다.

FMI는 실행/변수 접근 인터페이스이고 모든 모델의 변수명·단위·장치 기능 의미를 통일하지 않는다. 재사용 가능한 실행기는 공유하고 모델별 차이는 매핑·어댑터로 처리한다. 아직 제공되지 않은 CMMT FMU의 버전·동작을 가정하지 않는다.

## 시간·장애·복구

모델 계산은 외부 EtherCAT 입력 및 내부 시간 진행 계약에 따른다. DT 렌더링이 계산 시간을 결정하지 않는다. 현재 Copley의 2ms 내부 step과 잔여 시간 처리 등 제약은 [RF-017](../RF/RF-017-copley-fmu.md)을 따른다.

RF-018에서 모델 오류/지연·Host 정지/종료 시 Slave 통신 유지, 축 Fault 표시, 실행 가능한 축의 Reset 및 수동 Docker 복구를 검증했다. 늦은 응답을 정상 최신값처럼 재사용하지 않는다. 현재 자동 Host 재연결·운전 재개·위치 복원 기능은 없다. IO의 입력 유효성·출력·진단/Reset 의미는 프로파일별로 정의한다.

프로세스 분리나 Docker가 하드 실시간성·축별 프로세스 격리·모든 NIC 장애의 응답을 보장하지 않는다. 기존 검증 조건은 유지하고 새 IO/모델 조합의 영향은 별도 시험한다.

## 외부 상태 정렬과 모델 초기화

Soft ESC는 일반 장치 명령과 피드백을 제공한다. 모델 내부 상태 덮어쓰기·External Follow·실제 장치 스냅샷 초기화 API는 이번 범위에 없다. 외부 정렬은 [ADR-002](ADR-002-mode-switching.md)의 지원 경계를 따른다. 초기화 시 저장 파라미터 복원과 운전 위치·명령 복원은 구분한다.

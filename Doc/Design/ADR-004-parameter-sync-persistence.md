# ADR-004 — Soft ESC 장치 파라미터와 매핑 저장

- 결정 상태: **채택** (현행 범위 기준; 본문의 보류·과거 제안은 구분)
- 결정일: 2026-09-15
- 갱신일: 2026-11-25
- 구현 상태: RF-010 파라미터 및 RF-014 축 매핑 저장·복원 검증 완료. IO 저장 계약은 RF-013, 관리 API/이력은 RF-019/020 후속.

## 제품 책임

Soft ESC는 가상장치의 지원 파라미터를 읽기/쓰기·검증·저장·복원한다. 실제 장치 접근, 양방향 비교/복사·Pairing 정책은 외부 책임이다. DT나 Motion Server의 파일/설정을 읽거나 직접 수정하지 않는다.

외부 사용자가 일반 SDO를 통해 값을 설정할 수 있어야 한다. 값 적용·readback과 비휘발성 저장 성공은 구분한다. 모델에 적용하지 못한 쓰기를 성공으로 표시하지 않는다. 위치·속도 피드백·명령·Controlword·Fault 등 운전 상태를 설정 파라미터처럼 복사/저장하지 않는다.

## 두 저장 책임

| 데이터 | 소유자 | 계약 |
| --- | --- | --- |
| 동작 파라미터 | 기능 모델의 저장소 | 지원 객체만 명시적 저장; 저장 전 값 변경은 재시작 후 유지 보장 없음 |
| PDO mapping/assignment | EtherCAT Slave | 별도 매핑 파일; 마지막 저장 확정 매핑 복원; RF-014 활성화·실패 정책 적용 |

두 파일은 같은 데이터의 사본이 아니며 합쳐 저장하지 않는다. 매핑 저장이 동작 파라미터를 자동 저장하거나 그 반대 동작을 하지 않는다. 모델 IPC로 매핑 준비/활성화/저장 명령을 보내지 않는다.

## 설정·식별·복원

자체 .env의 `DEVICE_SIMULATOR_STATE_DIR=./state`를 사용한다. Docker 내부는 `/state`다. 축 파라미터 파일은 `DEVICE_SIMULATOR_AXIS_PARAMETER_SETS`의 논리 이름으로 state 바로 아래에 저장한다. 설정 JSON·state/parameters 예시는 현행 운영 계약이 아니다.

안정적인 장치 ID와 저장 공간의 호환 메타데이터로 식별한다. 버스 번호 변경만으로 다른 장치의 저장 데이터를 연결하지 않는다. 저장 공간 부재 시 지원 기본값으로 신규 생성하는 정책과, 기존 데이터 손상/누락/비호환 시 시작 오류 처리를 구분한다. 기존 데이터를 자동 초기화·이관하지 않는다. 과거 사용자 승인 하에 수행한 일회성 이관은 제품 자동 이관 기능이 아니다.

현재 파일 체크섬·원자 교체·fsync·저장 루트 단독 잠금과 저장 실패 검증 근거는 RF-010을 따른다. 파라미터 저장 실패는 성공으로 처리하지 않고 기존 정상 파일을 보존한다. 구체적인 오류/진단은 RF-018과 연계한다.

## 현재 모델 범위

F-KR CMMT와 Copley 모두 Profile Velocity(0x6081)를 저장한다. 모델별 저장 목록과 지원 스키마는 RF-010 및 각 모델 계약을 따른다. 전체 OD를 일괄 영구화하지 않는다. 기존 CMMT 호환 저장 명령의 의미를 다른 IO 장치에 그대로 적용하지 않는다.

Remote I/O는 모듈/채널 구성, 동작 파라미터와 실행 중 DO/DI·센서 상태를 구분한다. 어떤 값을 저장하고 어떤 SDO/명령으로 저장하는지는 RF-013의 선정 장치 계약에서 확정한다. 기존 축 저장 지원이 IO 저장 구현 완료를 뜻하지 않는다.

## 외부 초기화와 경계

외부 Master가 연결 초기화 때 파라미터/PDO를 재설정할 수 있으므로 저장 복원 직후와 Master 초기화 후를 구분해 검증한다. Master의 명시적 쓰기와 Soft ESC의 복원 동작이 값을 반복 덮어쓰지 않도록 사용 계약에 기록한다.

DT Demo의 Parameter Pairing은 지원 SDO·readback·저장 기능을 사용하는 사례다. PDO 변경은 PRE-OP 및 프로세스 이미지 재구성이 필요한 별도 구성 절차이며 일반 동작 파라미터 복사와 구분한다. State Alignment를 위해 실행 위치/센서 값을 저장 파일로 덮어쓰지 않는다.

## 후속과 검증 근거

- [RF-010](../RF/RF-010-parameter-persistence.md): 현재 저장·복원·실패·수동 백업/복원 검증.
- [RF-014](../RF/RF-014-dynamic-pdo-mapping.md): 매핑 최초 실행·저장 확정·활성화·재시작 정책.
- [RF-013](../RF/RF-013-virtual-io.md): Modular Remote I/O 저장 계약.
- [RF-019](../RF/RF-019-parameter-management-api.md) / [RF-020](../RF/RF-020-parameter-history.md): 관리 API·revision/이력은 장기 후속이며 이번 IO 확장의 필수 조건이 아님.
- [RF-009](../RF/RF-009-parameter-sync.md): 과거 외부 양방향 연동 구상 이력. Soft ESC의 구현 목록에서 제외.

이 문서는 기존 양방향 동기화 관리자 설계에서 Soft ESC가 소유하는 저장 기능을 분리한 현행 기준이다. 기존 완료 기록과 검증 자료는 보존한다.

# DT-004 — 양방향 파라미터 동기화와 영구 저장

- 결정일: 2026-09-15
- 상태: 요구사항 합의, 상세 저장·전송 방식 미결정, 구현 전

## 목적과 범위

실제→가상으로 장비 설정을 재현하고, 가상→실제로 검증한 설정을 적용한다. 가상장치 파라미터는 시뮬레이터를 재시작해도 유지한다. 위치·센서 등의 실행 상태 동기화와 파라미터 동기화는 별도 기능이다. 모드 전환으로 설정을 자동 덮어쓰지 않는다.

## 책임과 경로

별도 연동 패키지의 파라미터 동기화 관리자가 원본·대상 장치 선택, 비교, 적용 및 결과 확인을 담당한다. 실제 장치 접근은 Motion Server의 기존 공개 API를 사용한다. 대상별 SDO 읽기·쓰기 및 필요한 장치 상태 제어 지원 여부는 RF-005에서 확인하며 서버 수정 또는 별도 Master의 동시 버스 접근을 전제로 하지 않는다.

가상장치 영구 저장소는 시뮬레이터가 관리한다. EtherCAT 쓰기와 관리 인터페이스 쓰기는 공통 파라미터 적용·저장 정책을 따른다. 라우터가 저장 파일을 직접 수정하지 않는다. 동기화 관리자에서 저장 결과와 적용 revision을 확인할 수 있어야 한다.

## 비교 및 적용 절차

1. 방향, 원본·대상 장치, 대상 항목을 명시적으로 선택한다.
2. 장치 종류·revision·파라미터 스키마·단위·범위·지원 여부를 확인한다.
3. 양쪽 값을 읽어 차이와 적용 가능 여부를 표시한다.
4. 적용할 항목을 확정하고 대상의 변경 전 값을 백업한다.
5. 장치별 쓰기 조건을 충족한 상태에서 의존 순서에 따라 적용한다.
6. readback으로 확인하고 영구 저장 여부를 별도로 확인한다.
7. 적용·실패·미적용·복원 결과를 항목별 기록한다. 자동 운전 재개는 하지 않는다.

비교 이후 값이 변경된 경우 재비교하여 오래된 비교 결과로 덮어쓰지 않는다. 모드 전환·초기화·파라미터 적용의 동시 실행은 직렬화한다. 다항목·양쪽 장치에 대한 원자적 적용을 보장한다고 가정하지 않는다. 일부 실패 시 가능한 복원 범위를 명시하고 실제 결과를 다시 읽는다.

## 항목 분류

| 종류 | 정책 |
| --- | --- |
| 속도·가감속·이동 제한 등 설정 | 장치별 허용 목록과 쓰기 조건에 따라 동기화 |
| 단위·기어비·좌표 설정 | 의존 항목을 묶어 일관성 검증 |
| 식별 정보·읽기 전용 값 | 호환성 비교만 수행 |
| 위치 피드백·Statusword·Controlword·진행 명령 | 파라미터 저장·복사 대상에서 제외 |
| PDO 매핑·통신 설정 | 일반 파라미터 동기화에서 제외하고 별도 구성 절차로 관리 |
| 비휘발성 저장·재시작 필요 설정 | 값 적용과 영구 저장·재시작 결과를 구분 |

실제 장비의 RAM 적용 성공을 비휘발성 저장 성공으로 간주하지 않는다. 저장 명령과 지원 여부는 장치별로 확인한다. 모든 OD 객체를 무조건 복제하지 않는다.

## 가상장치 영구 저장소

저장소를 다음 세 계층으로 구분한다.

- 배포 기본값: 장치 프로파일에 포함된 초기 설정. 일반 실행 중 수정하지 않는다.
- 장치별 영구 파라미터: 사용자가 확정한 설정. 재시작·재빌드와 무관하게 유지한다.
- 실행 상태: 위치·속도·센서·상태 머신·대기 명령. 일반 파라미터 저장에 포함하지 않는다. 전환용 스냅샷은 별도 관리한다.

영구 저장 위치는 설정 가능한 데이터 디렉터리로 둔다. build, 진단 run-id 폴더, 임시 소켓 디렉터리 및 소스 체크아웃에 종속시키지 않는다. 컨테이너 실행 시 외부 영구 볼륨을 사용한다. 현재 구현은 storage.directory로 경로를 지정하고 parameter_set별 JSON 파일을 사용한다. 상대 경로는 구성 JSON 기준이며 예제는 state/parameters를 사용한다.

장치 정체성은 안정적인 instance ID로 관리하고, 영구 저장 공간은 JSON parameter_set의 논리 이름으로 매핑한다. 버스 순번·축 번호만으로 저장 대상을 식별하지 않는다. 장치 종류·프로파일/스키마 버전, 파라미터 타입·단위·값, 설정 revision, 변경 시각·출처 및 이전 revision을 관리한다. 형식과 이력 보존 기간은 상세 설계에서 정한다.

파라미터 쓰기는 실행 중 모델 값에 반영하고, 명시적 저장 명령이 지정된 parameter_set에 영구 반영한다. 저장 전 재시작은 마지막 저장값을 복원한다. 동기화 완료에는 모델 readback과 저장 성공 확인을 포함한다. 임시 시험값은 명시적으로 구분한다. SDO 쓰기 응답과 디스크 저장 시점, 다항목 commit 방식은 상세 설계에서 정의하며 저장 실패를 성공으로 숨기지 않는다.

## 재시작 복원 및 오류 처리

시작 시 장치 식별·스키마 확인 → 기본값과 호환 가능한 저장 설정 로드 → 의존성·범위 검증 → 모델 초기화 → 적용 revision 및 준비 상태 공개 순서로 진행한다. 기존 저장값은 배포 기본값보다 우선한다. 최초 장치 생성에 한해 기본값으로 시작하며 공장 초기화는 별도 명시적 작업이다.

parameter_set 저장 공간이 없으면 타입·모델·mode에 맞는 기본값으로 신규 생성한다. 기존 공간 내부 데이터의 손상·누락·버전 불일치는 신규 공간으로 취급해 덮어쓰지 않는다. 운전 준비 완료를 내보내지 않고 복구·이관 필요 상태를 표시한다. 원자적 파일 교체 또는 DB transaction 등으로 불완전 기록을 방지하고, 동시 쓰기를 제어하며 이전 정상 revision을 보존한다. 현재는 파일 fsync·원자적 교체·체크섬·저장 루트 단독 잠금을 구현했다. 이전 revision 이력 보존·백업/이관은 후속이며 전체 요구 충족으로 간주하지 않는다.

Motion Server 연결 초기화가 설정을 재기입할 수 있으므로 복원 직후뿐 아니라 서버 연결 후 값도 검증한다. 서버가 덮어쓰는 설정의 소유권·우선순위를 명시하며 복원과 서버 초기화가 서로 값을 반복해서 바꾸게 하지 않는다. 기존 서버 설정만으로 조정할 수 없는 충돌은 미해결 전제로 기록한다.

## 현재 축 범위의 추가 합의 (2026-09-22)

parameter_set은 preset 초기값이 아닌 영구 저장 공간의 논리 이름이다. 초기에는 여러 장치의 동일 공간 참조를 거부한다. JSON에 별도 scale/counts_per_unit을 두지 않고 장치 파라미터 모델의 단위·변환 설정을 사용한다. IO 및 센서 저장 정책은 [RF-013](../RF/RF-013-virtual-io.md)에서 별도로 재논의한다.

## 초기 구현 경계

RF-011 연계 초기 구현은 NON_PDO_CONFIGURATION_OD_ROLES 20개 값만 저장한다. 0x2005:03=1 및 0x2005:01=1 요청을 수신하면 파일 저장이 완료된 후 성공 상태를 설정한다. 미지원 selection·저장 실패는 성공으로 처리하지 않으며 현재 IPC는 fail-closed다. 정상 오류 Abort 호환성은 TD-001의 잔여 작업이다. 운전 상태 복원, 전체 OD 저장, 0x2000 reset 의미 변경, revision 이력/관리 API는 이번 구현에 포함하지 않는다. 자세한 검증 경계는 RF-010을 따른다.

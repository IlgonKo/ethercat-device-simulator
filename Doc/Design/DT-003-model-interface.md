# DT-003 — 장치 모델 경계와 FMI 확장

- 결정일: 2026-09-15
- 상태: 책임 경계 및 확장 방향 합의, 인터페이스 상세 미정

## 확정 방향

축·IO 장치 동작은 Omniverse가 아닌 시뮬레이션 모델에서 계산한다. 현재 가상축·가상 IO를 재사용하고 향후 Functional Mock-up Interface(FMI) 기반 모델과 호환할 수 있도록 어댑터 경계를 둔다. 현재 FMI 호환성이나 가상 IO의 EtherCAT·DT 연결이 검증되었다는 의미는 아니다.

## 계층

- KickCAT: EtherCAT 프레임, ESC, Mailbox 및 PDO 통신.
- 장치 계층: OD·CiA 402와 명령·상태 변환. 기존 VirtualOdBridge와 가상 서보의 역할을 분석해 경계를 정리한다.
- 실행 계층: 모델 초기화, 입력 적용, 시간 진행, 출력 수집, 리셋·종료.
- 모델 어댑터: 현재 가상축·가상 IO와 향후 FMI 모델을 내부 실행 계약에 연결.
- DT 연결: 라우터에서 선택된 피드백을 Omniverse에 표시. 장치 동작을 중복 계산하지 않음.

현재 C++ KickCAT ↔ Unix 소켓 ↔ Python 모델 구조를 출발점으로 사용한다. 공통 모델 패키지의 배포·의존성 경계는 후속 결정이며 Motion Server 제품 코드 변경이나 모델 코드의 무관리 복제를 전제로 하지 않는다.

## 전환용 관리 인터페이스

EtherCAT 명령 경로와 구분되는 모델 관리 인터페이스에서 정지 상태의 초기화를 제공한다. 위치만 덮어쓰지 않고 필요한 내부 상태·센서·출력 일관성을 검증한다. 장치 식별, 스냅샷 버전·시각·단위, 필수 값 검증, 적용 결과와 오류를 상세 계약에 포함한다. 구체적 전송 방식과 스키마는 미결정이다.

## 시간과 환경 입력

모델 계산 주기와 Omniverse 화면 갱신을 분리한다. 렌더링 속도가 모델 시간을 결정하지 않도록 한다. 모델 주기·외부 입력 샘플링·지연 처리의 상세 정책은 후속 설계에서 정한다.

Omniverse 접촉 이벤트나 사용자 조작을 모델의 환경 입력으로 전달하는 것은 향후 확장 후보이다. 역방향 연동을 초기 구현 완료 조건으로 간주하지 않는다. 도입 시에도 최종 장치 상태는 모델이 결정한다.

## FMI 후속 결정

FMI 채택 방향만 확정한다. 버전, 실행 방식, 지원 변수형, 모델 수명 주기, 상태 초기화·복원 지원, 시간 진행과 배포 방식은 미결정이다. 현재 인터페이스를 FMI 표준 구현으로 표현하지 않는다. 지원 모델의 초기화 능력이 모드 전환 정책을 충족하는지 별도 검증한다.

관련: [상태 초기화·전환 RF-007](../RF/RF-007-mode-switching.md), [Omniverse RF-008](../RF/RF-008-omniverse-sync.md).

## 파라미터 영구 저장

재시작 때 장치 설정이 초기화되지 않도록 시뮬레이터가 안정적인 장치 ID 기반 영구 저장을 관리한다. 모델은 검증된 저장 설정으로 초기화하며 실행 상태는 별도 취급한다. [DT-004](DT-004-parameter-sync-persistence.md)의 기본값·영구 설정·실행 상태 경계 및 저장 실패 정책을 따른다. 향후 FMI 어댑터도 지원 가능한 파라미터 적용·복원 능력을 명시한다.

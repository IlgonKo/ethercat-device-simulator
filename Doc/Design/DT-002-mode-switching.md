# DT-002 — 모드 전환과 상태 동기화

- 결정일: 2026-09-15
- 상태: 정책 합의 완료, 구현 전
- 관련: [전체 구조](DT-001-system-architecture.md), [RF-007](../RF/RF-007-mode-switching.md)

## 기준 원칙

선택한 장치가 상태의 기준이며 DT가 그 피드백을 따른다. 초기 버전은 정지 상태에서만 전환하고 진행 중인 이동 명령을 이어받지 않는다. 명령 대상과 리드백 출처를 하나의 전환으로 함께 변경한다.

## 실제 → 가상

1. 새 동작 명령 접수를 막고 실제 장비의 정지를 확인한다.
2. 유효한 위치·IO·필요 장치 상태를 스냅샷으로 수집한다.
3. 시뮬레이터 관리 인터페이스로 가상 모델의 내부 상태를 초기화한다.
4. 모델 상태의 일관성과 전환 조건을 확인한다.
5. 가상 그룹으로 라우팅을 전환하고 DT에 새 상태를 적용한다.

PDO 리드백을 덮어써 초기화를 위장하지 않는다. 실제 상태만으로 복원할 수 없는 모델 내부 상태나 물체 배치는 별도 초기 조건을 요구한다. 필요한 상태가 없으면 해당 전환을 허용하지 않는다.

## 가상 → 실제

가상 동작을 정지하고 실제 장비의 현재 상태와 대기·정지 조건을 확인한다. 실제 그룹으로 라우팅을 전환하고 DT를 실제 상태에 맞춘다. 실제 장비를 가상 위치로 자동 이동시키거나 가상 IO 출력을 자동 적용하지 않는다. 실제 위치 맞추기가 필요하면 모드 전환과 분리된 명시적 이동 작업으로 다룬다.

## 상태별 정책

| 상태 | 처리 |
| --- | --- |
| 축 위치 | 단위·좌표 원점·기어비 대응을 확인해 모델 내부 위치를 설정 |
| 속도·진행 명령 | 정지 확인 후 전환, 대기 명령·궤적을 이어받지 않음 |
| 센서 | 직접 설정 입력과 모델 계산 출력을 구분. 계산형 센서는 모델 상태에서 재계산 |
| 출력 | 연결된 밸브·실린더 등 모델 상태와 함께 일관성을 확인 |
| CiA 402 / Statusword | 비트 복사 대신 모델 상태 전이로 생성 |
| Fault·알람 | 전환 가능 판단에 사용, 가상 Fault 주입과 분리 |
| Homing·파라미터 | 좌표 및 설정 의미의 일치 확인. referenced 비트만 복사하지 않음 |

## 전환 절차와 실패

라우터는 실제 / 가상 / 전환 중 상태를 구분한다. 새 명령 차단 → 기존 대상 정지 확인 → 기존 요청 정리 → 새 대상 유효성·제어권 확인 → 필요한 초기화 → 명령·피드백 전환 → DT 새 상태 적용 → 명령 재개 순서로 처리한다.

전환 중 실패하면 명령을 차단한 상태를 유지하고 원인을 표시한다. 정지가 확인되지 않은 경우 정지 완료로 표시하지 않는다. 자동 재개 또는 다른 그룹 구동을 하지 않는다. 복구·재시도 절차는 상세 설계에서 정한다. 전환 세션으로 이전 명령·응답·리드백을 구분해 새 모드에 섞이지 않도록 한다.

DT는 모드 변경을 실제 이동처럼 보간하지 않고 전환 중 표시 후 새 기준 상태를 적용한다. 통신·상태가 오래되거나 유효하지 않으면 그 상태를 표시한다.

## 미결정 상세 조건

정지 판정 임계값·유지 시간, 스냅샷 시간 정합성·유효 기간, 필수 상태 목록, 장치별 대기 상태, Fault 시 전환 허용 범위, 전환 시간 제한, DT 적용 확인 방법은 구현 전에 명세한다. 전체 물리 상태의 완전 복원과 움직이는 축의 연속 전환은 초기 범위에 포함하지 않는다.

## 파라미터 동기화와의 경계

전환 시 파라미터 호환성을 확인하되 자동으로 덮어쓰지 않는다. 변경이 필요하면 [별도 양방향 동기화](DT-004-parameter-sync-persistence.md)를 수행한다. 동기화·전환·초기화는 동시에 적용하지 않으며 위치·센서 스냅샷을 영구 파라미터와 혼합하지 않는다.

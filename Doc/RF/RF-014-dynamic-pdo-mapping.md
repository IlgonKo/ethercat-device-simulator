# RF-014 — 동적 PDO 매핑 지원

- 등록일: 2026-09-22
- 상태: 계획 / 미착수
- 현재 대상: 가상축. 가상 IO는 RF-013의 별도 보류 범위.
- 관련: [RF-004](RF-004-motion-server-axis-panel.md), [RF-011](RF-011-device-configuration.md), [TD-001](../TD/TD-001-sdo-abort-response.md)

## 문제와 목표

현재 CMMT 시뮬레이터는 motion_server_default(Rx 24 / Tx 14바이트)의 동일 구성 clear/rewrite/restore만 지원한다. 다른 매핑 값을 쓰면 FixedMapping 검사에서 실패 종료할 수 있다. Master가 매핑 객체를 변경해도 통신·모델 데이터 배치가 자동 갱신되는 구조는 아니다.

Master가 SDO로 장치가 지원하는 범위의 PDO 항목·순서·구성을 변경하면, 검증 후 실제 process image와 모델 연결을 새 배치에 맞춰 동작시키는 것이 목표다. '동적'은 지원 상태에서 수행하는 재매핑을 뜻하며 OP 중 임의 실시간 변경이나 모든 OD 매핑을 허용한다는 의미가 아니다.

## 작업 범위

- 가상축 프로파일별 기본 PDO, 매핑 가능한 OD 항목, 방향·비트 길이·접근 조건·크기 상한을 정의한다.
- PDO mapping/assignment 객체의 SDO 쓰기 및 count clear/restore 절차를 처리한다. 우선 PRE-OP 재설정을 기준으로 상세 허용 상태를 확정한다.
- 새로운 RxPDO/TxPDO의 길이·순서·오프셋 및 필요한 SyncManager/FMMU 연계를 처리한다.
- C++ 통신 계층과 Python VirtualOdBridge/모델의 encode/decode 계약을 새 배치로 함께 갱신한다. 메타데이터만 변경하고 기존 고정 해석을 유지하지 않는다.
- 불완전한 재설정·미지원 항목·방향/길이 오류·잘못된 상태 요청을 정의된 오류로 거부한다. 실패 시 유효 구성의 유지·복원 또는 비운전 상태 유지 정책을 정한다.
- 다축 환경에서 한 Slave의 매핑 변경이 다른 Slave의 데이터 해석에 영향을 주지 않도록 한다.

JSON의 pdo 필드 존재/제거 결정과 동적 매핑 구현은 별개다. 이 RF 등록으로 구성 스키마나 기존 Motion Server API를 변경하지 않는다. 장치 초기 기본 매핑과 재시작 시 매핑 처리 정책은 구현 전에 명시한다.

## TD-001과의 경계

TD-001은 기존 SDO Abort 응답 형식과 PySOEM 호환성을 다룬다. 이 RF는 잘못된 매핑을 검출하고 적절한 Abort를 생성·전달하는 동작을 추가한다. TD-001만 해결해도 현재 실패 종료 경로가 자동으로 정상 Abort로 바뀌는 것은 아니다.

오류 응답 완료 검증에는 TD-001 해결 또는 동등한 검증된 오류 응답 경로가 필요하다. PacketError를 정상 Abort로 간주하는 Master 우회는 사용하지 않는다. KickCAT 변경/래핑 위치 등 구현 방식은 별도 설계한다.

## 완료 기준

- [ ] 지원 OD·크기·매핑 객체·상태·설정 완료 조건을 문서화.
- [ ] 기존 기본 매핑의 동일 재설정 및 기존 SDO/PDO 회귀 통과.
- [ ] 지원 항목의 순서 변경과 추가/제거로 기본값과 다른 유효 매핑을 설정하고 readback 확인.
- [ ] 변경 후 PDO 크기·오프셋·OD 값 해석 및 모델 동작 일치 검증.
- [ ] 실제 PySOEM에서 OP 전환·기대 WKC·PDO 왕복 검증. 시험용 Master 사용 시 기존 Master와 동시에 버스를 점유하지 않음.
- [ ] 미지원 OD·길이·방향·상태·불완전 설정에 대한 정상 Abort 및 프로세스 생존/비운전 상태 정책 검증.
- [ ] 재설정 실패 후 복원·재시도와 재시작 기본 매핑 정책 검증.
- [ ] 다축에서 매핑 변경 및 PDO 처리가 Slave별로 분리되는지 확인.

## 미결정·제외 범위

첫 지원 항목 목록, padding/비바이트 정렬, 복수 PDO·SyncManager, Complete Access 쓰기, 모델 필수 항목 누락 시 동작, commit/rollback 방식은 구현 전에 확정한다. 무제한 임의 매핑, 가상 IO, OP 중 재매핑, DC/CSP 실시간 성능 보장은 자동으로 범위에 포함하지 않는다.

## 검증 기록

아직 구현·시험하지 않았다. RF-004의 기본 고정 매핑 성공을 동적 매핑 검증으로 취급하지 않는다. 이번 등록은 구현 착수를 의미하지 않는다.

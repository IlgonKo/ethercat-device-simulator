## 목적과 적용 범위

축 동작 모델의 명령·상태·정지·재개·위치 제한·Homing·Fault Reset·파라미터 반영 정책과 Motion Server 호환성을 정의·검증한다. F-KR CMMT 직선축의 차이를 수정하고 Copley는 기존 지원 범위에서 대조·회귀한다. 공통 정책을 기록하는 것이 모든 동작 모델의 지원 모드를 늘린다는 의미는 아니다.

| 대상 | 이번 적용 |
| --- | --- |
| F-KR CMMT | PP/PV/Jog/Homing, 정지·모드·한계·설정 적용·Fault Reset 정책 구현·검증 |
| Copley | 기존 PP/Reset/파라미터·혼합 운전 회귀 및 정책과의 차이 명시. PV/Jog/Homing 또는 미지원 Halt 추가 제외 |
| Motion Server | 명령 경로 읽기·호환성 검증만 수행. 코드 수정은 별도 프로젝트 |
| EtherCAT 공통 기반 | RF-014 단일 OD·SDO/PDO·매핑, RF-018 장애 격리의 기존 완료 근거 유지 |

3축은 독립성 시험 구성이며 제품의 최대 축 수가 아니다. 회전축 modulo·연속 회전·최단 경로, CSP 확장, blending·보간, 실제 CMMT 전체 사양 재현은 제외한다. 기존 CSP/회전 기능을 묵시적으로 삭제하지 않는다. 외부 경로 계획·한계 접근 감속·Pairing/Alignment·DT 연동은 상위 애플리케이션 책임이다.

[RF-022](RF-022-f-kr-cmmt-fmu.md)는 별도 FMU 제작/연결 항목이다. 이 문서는 RF-015 정책·현재 코드 차이·수정 순서·합격 기준을 다룬다. 이 검토를 FMU 구현 착수로 해석하지 않는다.

## 정책의 우선순위와 이번 정리

날짜별 제안을 누적하던 본문을 아래 현행 계약으로 통합했다. 이전 논의 이력은 [작업 일지](../Work_log.md)에 남긴다.

- PP OD 목표 변경이나 이동 중 새 시작 요청만으로 현재 이동을 정지시키지 않는다. 최신 합의인 '현재 실행 프로파일 유지·새 요청 무시'를 우선한다.
- 위치 한계의 운전 중 즉시 적용 제안은 폐기했다. 한계는 운전 시작 시 확보하고 이후 설정값은 다음 운전에 적용한다.
- 이동 중 모드 변경은 오류가 아니라 무시다. 정지 후에도 PDO 요청값이 유지되면 그때 적용한다.
- 운전 제한에 의한 정지, 일반 정지 및 모드별 정상 목표 도달을 구분한다.
- 아래 현행 계약의 구현·검증을 완료했다. 세부 경계는 자동 시험, 일반 명령/저장/혼합 통신은 물리 통합 근거로 구분하며 전 항목의 물리 반복 완료를 뜻하지 않는다.

## 1. OD 설정값과 실행 상태

장치당 공개 OD는 하나다. 현재 PP 목표·프로파일, 적용 중 한계, 정지 감속값은 실행 상태이며 별도 OD나 영구 저장소가 아니다.

- 검증된 SDO 쓰기는 OD에 반영하고 성공 후 readback에서 확인한다. 계산 주기 도중 일부 값만 변경하지 않는다.
- SDO/PDO 입력 경로 차이만으로 동작 의미를 바꾸지 않는다. PDO 매핑된 값은 이후 PDO로 다시 갱신될 수 있다.
- 여러 SDO 쓰기는 개별 요청이며 일괄 원자 적용을 보장하지 않는다.
- 설정 변경과 영구 저장은 별개다. 기존 파라미터 저장·복원 계약을 유지한다.

## 2. PP 명령과 실행 프로파일

- 정지 후 새 PP 시작 요청을 수락할 때 목표 위치 0x607A, 속도 0x6081, 가속 0x6083, 감속 0x6084, 위치 한계 0x607D를 확보한다.
- 이동 중 위 OD 변경은 readback에 반영하되 현재 이동 목표·프로파일·한계는 유지한다. 새 값은 다음 PP 수락 시 적용한다.
- 이동 또는 감속 중 새 PP 시작 요청은 방어적으로 무시한다. 오류/Fault를 발생시키지 않고 현재 동작을 유지한다.
- 무시한 요청은 대기열에 저장하거나 정지 후 자동 실행하지 않는다. 정지 후 새로운 시작 edge가 필요하다.
- PP 수락 시 목표가 적용 한계 밖이면 이동을 시작하지 않고 제한 활성·Warning으로 표시한다. 이동 중 OD에 범위 밖 목표를 써도 현재 PP를 취소하지 않는다.
- 원점 미완료 상태에서는 PP를 시작하지 않는다.
- 완료 판정은 OD에 새로 써 둔 다음 목표가 아니라 현재 실행 목표를 기준으로 한다.
- 예: 속도 100으로 시작한 이동 중 0x6081을 50으로 쓰면 현재 이동은 기존 프로파일로 완료하고 다음 이동부터 50을 사용한다.

### Motion Server와의 책임 분리 — 사용자 최종 확인

Motion Server의 운전 중 PP 요청 차단(B8 Moving 확인)은 사용자가 해당 프로젝트에서 처리한다. Soft ESC는 서버의 차단 여부에 의존하지 않고 방어적 무시를 유지한다. 서버의 차단 구현을 RF-015 디바이스 정책의 선행 조건으로 삼지 않는다.

현재 확인한 서버의 일반 PP 경로는 Set-point acknowledge를 기다리므로, 디바이스가 새 요청을 무시하면 클라이언트 명령 실패가 반환될 수 있다. '디바이스에 오류/Fault 없음'과 '상위 API가 반드시 성공 응답'은 다르다. 이를 숨기려고 무시한 요청을 수락한 것으로 응답하지 않는다. 정상 순차 운전과 직접 중복 요청 방어 시험을 구분한다.

## 3. 소프트웨어 위치 한계

0x607D:01 하한·:02 상한을 사용하고 경계값 자체는 허용한다.

| 항목 | 현행 계약 |
| --- | --- |
| PP 한계 확보 | 새 PP 시작 요청 수락 시 |
| PV/Jog 한계 확보 | 정지 상태에서 새 운전을 시작할 때 |
| 운전 중 한계 변경 | OD/readback만 갱신. 현재 운전은 이전 한계 유지 |
| PV/Jog 속도·방향 변경 | 같은 운전으로 취급, 한계 다시 확보하지 않음 |
| 다음 운전 시작 위치가 새 범위 밖 | 안쪽 복귀만 허용. PP 목표는 범위 안이어야 함 |
| 하한 > 상한 | 해당 쓰기 거부·기존 값 유지. 자동 교환하지 않음 |

PV/Jog 상한에서는 양의 방향, 하한에서는 음의 방향 진행을 차단하고 감속 정지한다. 반대 방향 복귀는 허용한다. 한계 도달 후 감속하므로 감속 중 범위 초과가 가능하며 위치를 경계에 강제 고정하지 않는다. 한계 접근 전 감속 계획은 상위 책임이다.

한계 제한 자체는 Fault가 아니라 Warning/제한 활성이다. Enable을 유지하고 Fault Reset을 요구하지 않는다. 유효한 새 명령과 제한 조건 해소 후 표시를 해제한다. 한계 확장·모드 변경만으로 차단된 명령을 재개하지 않는다. PP는 새 시작 요청, PV/Jog는 정지 명령을 거친 새 운전 명령을 요구한다.

## 4. 정지·재개와 감속값

| 정지 종류 | 동작과 완료 후 상태 |
| --- | --- |
| 일반 Stop | 설정 감속 정지, Enable 유지, 새 운전 명령 대기 |
| Halt | 감속 정지·현재 이동 취소. Enable 유지. Halt 해제만으로 이전 이동 재개 금지 |
| Quick Stop | 0x6085 감속, 0x605A 옵션 2 동작만 지원. 정지 후 Switch On Disabled, Enable 절차와 새 명령 필요 |
| Disable Operation | 속도 즉시 0·현재 위치 유지, Switched On. 재Enable만으로 이전 이동 재개 금지 |

| 상황 | 확보할 감속값 |
| --- | --- |
| PP 정상 목표 도달 / PP Stop·Halt / PP 한계 정지 | 해당 PP 시작 시 확보한 0x6084 |
| PV/Jog Stop·Halt | 정지 요청 시점의 0x6084 |
| PV/Jog 한계 정지 | 한계 검출 시점의 0x6084 |
| Quick Stop | Quick Stop 요청 시점의 0x6085 |

정지 시작 후 OD를 변경해도 확보한 감속값은 완료까지 유지한다. 일반 감속 중 새 Quick Stop이면 그 순간의 0x6085로 전환하고 Disable이면 즉시 정지한다. Disable은 단순 동작 모델의 근사이며 토크 해제 후 관성 이동·수직축 낙하는 모델링하지 않는다.

정지 자체로 Fault를 만들지 않는다. 정지 완료와 원래 이동 목표 달성을 모드에 맞게 구분한다. Statusword의 모드별 의미를 유지하면서 중단된 PP를 원래 목표 도달 성공으로 잘못 판정하지 않도록 검증한다.

## 5. PV/Jog 속도·방향 변경

| 항목 | 현행 계약 |
| --- | --- |
| PV 목표 속도 0x60FF 변경 | 다음 주기부터 가감속 제한으로 새 목표 추종 |
| Jog 저속·고속 선택 변경 | 선택 속도로 가감속 전환 |
| 방향 반전 | 현재 방향 속도를 0까지 감속한 뒤 반대 방향 가속 |
| Jog 양방향 동시 ON / 모두 OFF | 목표 속도 0으로 감속 정지 |
| 일반 운전 중 가감속 설정 변경 | 다음 주기부터 적용. 위치·속도 순간 변경 없음 |
| Stop/Halt/한계 정지 중 설정 변경 | 이미 확보한 정지 감속값 유지 |

방향 반전은 별도 Fault나 재Enable을 요구하지 않는다. 반전 중 순간 속도 0은 새 운전 시작이나 정지 완료로 간주하지 않는다. 한계 차단 후 재개 조건이 우선한다.

## 6. 모드 변경

- 정지 중에만 적용한다. 이동·감속 중 요청은 오류/Fault 없이 무시하고 현재 모드·동작을 유지한다.
- 0x6060은 요청값, 0x6061은 실제 적용 모드다. 요청값과 적용값이 일시적으로 다를 수 있다.
- 정지 후에도 PDO 변경값이 유지되면 그때 적용한다. 별도 요청 대기열은 두지 않는다.
- 같은 값 반복 수신으로 실행 상태를 재초기화하지 않는다.
- 미지원 모드값의 기존 처리 정책까지 무시로 바꾸지는 않는다.
- 실제 계산은 요청값이 아니라 적용 모드로 실행해야 한다. 정지 판정은 속도값뿐 아니라 이동·감속·Homing 실행 상태와 함께 관리한다.

## 7. 가상 Homing·초기 상태·Fault Reset

| 항목 | 현행 계약 |
| --- | --- |
| 모델 생성/재생성·Docker 재시작 | 위치 0, 속도 0, Disable, 원점 미완료 |
| Homing 시작 | Enable·정지 상태에서만 허용 |
| Homing | 이동 없이 현재 위치의 좌표를 0으로 지정. 시뮬레이션 시간 0.1초 후 완료 |
| 완료 | referenced 표시, 이전 이동 취소, 새 명령 대기 |
| 진행 중 Stop·Disable·Fault | Homing 취소, 완료 처리 금지, 새 요청 필요 |
| 완료 후 Stop·Disable·모드 변경 | referenced 유지 |
| 일반 축 Fault Reset | 모델 위치가 보존된 경우 referenced 유지 |
| 원점 미완료 운전 | PP 불허, PV/Jog는 현재 좌표 한계 안에서 허용 |

좌표 30mm를 0으로 지정한 것을 30mm 이동으로 계산하지 않는다. 위치 한계는 변경된 좌표계에 적용하고 저장 한계값은 자동 변경하지 않는다. 실제 센서 탐색·Homing Method별 움직임·Home Offset 확장은 제외한다.

Copley는 기존 항상 referenced 표시·실제 Homing 미지원 정책을 유지한다. Host/모델 실행 장애는 RF-018대로 수동 Docker 재시작 대상이며 축 Fault Reset으로 해제하지 않는다.

## 8. 단위·설정 호환성

EtherCAT OD/SDO/PDO는 기존 원시 정수·단위 설정을 유지한다. F-KR 어댑터가 기존 OD 기준으로 변환하고 동작 모델 경계는 위치 m, 속도 m/s, 가감속 m/s², 시간 s를 사용한다. Controlword/Statusword/Mode는 정수·비트로 유지한다. 별도 counts_per_unit 설정은 추가하지 않는다.

Copley는 해당 FMU 정의 단위를 기존 어댑터에서 변환한다. 단위 설정 객체의 접근 권한을 임의 확대하지 않는다. 이번 확인에서 0x216E:01·0x2194:01은 읽기 전용이었다. 새로운 단위 쓰기 기능을 논의·구현할 필요 없이 기존 계약을 보존한다.

| C. 한계/PV/Jog | PV 위치 차단 없음, Jog 실시간 OD 한계 조회, 역전 한계 자동 교환, 반전 시 0 경유 단계 미분리 | 운전별 한계 확보·방향 차단·복귀·감속 고정·반전 처리·설정 검증 |
| D. 정지/Quick Stop | 공통 즉시 정지·완료 표시 혼용, 감속값 실시간 재조회, Quick Stop 상태 없음 | 명시적 정지 원인·완료 구분, 감속값 확보, Quick Stop 상태 전환·관련 OD 지원 |
| E. Homing/Reset | cycle count 기반 0.1초, 시작 시 정지 검증/중단 처리가 부족 | 시뮬레이션 누적 시간, 시작 조건·취소·좌표 기준·referenced 보존 검증 |
| F. 단위/공통 회귀 | 모델이 OD 변환 지수 직접 참조 | 어댑터 변환 계약 적용, 기존 원시값/readback·저장·매핑·장애 처리 회귀 |

Quick Stop 0x605A(int16, 옵션 2만)·0x6085(uint32, 양수)를 F-KR OD/SDO와 영구 저장에 포함했다. 생성 기본값은 프로파일의 0x6084 기본값이다. F-KR 저장 스키마 3/23개 OD를 사용하며 구형 파일은 자동 보정 없이 거부한다. 기존 오프라인 이관 유틸리티는 원본 백업·검증·원자적 저장을 수행한다. 이번 벤치는 정지 후 명시적으로 이관했고 기존 값은 모두 보존했다. Copley 저장 스키마는 변경하지 않았다.

추가 정책 질문을 반복하기보다 합의 범위에서 구현·시험으로 해소한다. 제품 동작을 바꿔야 하는 충돌이 새로 확인되면 분리한다. 5단계에서 새 이미지 적용과 벤치 저장 파일 이관을 수행했다. 임시 F-KR 3축/advanced 시험 후 원래 구성/basic 모드로 복원했다. Motion Server 소스는 수정하지 않았다.

## 2026-11-26 — Motion Server 신규 요청 제한과의 호환성 검토

사용자 제공 서버 정책을 검토 기준으로 사용한다. 확인한 로컬 checkout에 새 제한 구현이 반영됐다고 주장하지 않는다.

- PP/PV 신규 명령·Homing 시작·모드 변경은 정지 중에만 허용.
- move_vel(0)도 신규 PV 명령 제한의 예외가 아니다. 운전 중 정지는 Stop API를 사용.
- Jog 예외는 이미 Jog 모드인 동안의 운전 명령만 해당한다. Jog 진입/이탈의 모드 변경은 정지 중에만 허용한다.
- Stop/Disable은 운전 중에도 허용. CSP는 이번 변경에서 제외.

### 정책 대조

F-KR 합의 정책과 호환된다. 서버가 운전 중 PV API 요청을 제한하더라도, 디바이스는 PDO 목표 속도 갱신을 계속 처리한다. Stop이 PV target_velocity=0을 전송하는 기존 경로를 차단하면 안 된다. API 요청 제한과 cyclic PDO 처리 제한은 별개다. RF-015의 직접 PDO 속도 변경·방향 반전 시험은 디바이스 계약 시험으로 유지한다.

정상 순차 PP와 Homing 시작/모드 전환 조건은 일치한다. 디바이스 중복 PP 방어적 무시는 유지한다. Jog 방향/속도 변경은 계속 허용하되 모드 변경 시 실제 정지와 0x6061 적용 상태를 확인한다. 모드 복원용 고정 cycle 대기를 실제 정지 확인으로 간주하지 않는다.

### 현재 구현에서 확인된 Copley 호환성 차이

실제 CopleyDriveSim-linux.fmu를 오프라인으로 실행한 결과, PP 운전 중 위치/속도가 증가해도 Statusword B8이 OFF였다. 어댑터는 FMU Statusword에 referenced만 추가하므로 B8 기반 서버 차단만으로 Copley 운전 중 요청을 막을 수 없다.

또한 기존 Copley 어댑터는 Halt를 제거하므로 PP Stop(Halt) 후에도 이동이 계속됨을 관찰했다. Disable Operation에서는 속도0/위치 정지를 관찰했다. 이 결과는 F-KR 정책을 수정할 사유가 아니라 Copley의 실제 지원/표시 차이로 분리한다. B8 투영과 Stop 지원 보완 여부는 별도 구현 범위로 명시해야 하며 이번 검토에서 추가 구현하지 않았다.

F-KR 1~5단계 구현과 새 이미지의 정지/재개 물리 통합 시험을 완료했다. basic 모드의 Enable은 0x000F만 쓰므로 초기 Switch On Disabled 및 Quick Stop 이후에는 Reset→Enable 순서를 사용한다. Quick Stop 직접 CW 시험은 임시 advanced 모드에서 수행한 뒤 원래 basic으로 복원했다.

## 2026-11-26 최종 완료 판정

사용자는 기존 자동 시험과 물리 통합 근거로 추가 반복 없이 완료 처리하는 데 동의했다. RF-015의 필수 구현·검증 잔여 항목은 없다. [RF-022 실제 FMU 비교](../Validation/RF-022/stage1-4-20261126.md) 및 [물리 통합](../Validation/RF-022/stage5-20261126.md)은 FMU 전환 후 회귀 근거로 연결한다.

Copley의 Moving B8 표시/Halt 미지원 차이, 회전 modulo·최단 경로 확장, CSP 확장, 물리 토크/하중 모델과 RT 보증은 완료 범위에 포함하지 않는다. DT Demo의 PP/PV/Jog/Homing/정지 요구에는 F-KR 직선 FMU를 사용하며, Copley는 기존 지원 범위의 교체/혼합 모델로 유지한다.

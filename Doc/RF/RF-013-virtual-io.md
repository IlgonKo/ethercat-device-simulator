# RF-013 — EtherCAT Modular Device Profile 기반 Remote I/O

- 현재 상태: **완료**
- 상태 상세: 2026-11-26 합의 범위의 구현·검증 완료. CPX 고정 PDO/SDO·실제 실린더/아날로그 지연 FMU·혼합 운전·Host 장애/복구·모듈 재구성/재검색·원복을 확인했다. 아날로그 수동/물리 AO→FMU→AI 왕복은 사용자 결정으로 생략했으며 미검증 한계로 유지한다. [5단계 종합](../Validation/RF-013-stage5-20261126.md), [최종 재구성 시험](../Validation/RF-013-reconfiguration-20261126.md).
- 등록일: 2026-09-22
- 설계: [ADR-001](../Design/ADR-001-system-architecture.md), [프로젝트 계획](../project-plan.md), [ADR-005](../Design/ADR-005-device-configuration.md)

## 제품 범위와 이번 구현

EtherCAT Modular Device Profile 기반 Remote I/O를 CiA402 Drive와 함께 독립 제품 범위로 지원한다. 1차 구현 대상은 CPX-AP-I(EtherCAT 연결: CPX-AP-I-EC)이며 모듈 구성과 DI/DO/AI/AO를 제공하고 모델별 어댑터로 동작 모델에 연결한다. Analog IO를 후속으로 미뤘던 이전 범위는 이 결정으로 대체한다. 단순 DI/DO 바이트 교환만으로 Modular Device Profile 지원을 완료했다고 표시하지 않는다.

- 공통 모듈형 프로파일: 장치/모듈 구성·식별·지원 객체·프로세스 데이터 계약.
- 제품별 장치 설명: 실제 Identity·ESI·모듈 정의·제조사 확장·초기화 요구.
- 어댑터: 모듈/채널과 선택한 동작 모델 입출력·단위·실행 의미 연결.
- 동작 모델: 자체 모델/FMU/기타 형식으로 연결 대상 동작 계산. 현재 모든 형식의 범용 로더를 구현했다는 의미는 아님.

DT Demo의 Loader는 밸브/실린더 동작 모델의 검증 사례다. DO → 동작 모델 → DI 경로로 끝단 센서를 생성하며 DO echo로 대체하지 않는다. Loader·Orchestrator·Omniverse를 Remote I/O 프로파일의 실행 의존성으로 넣지 않는다. 연속 Loader 위치용 외부 통신은 이번 범위에서 추가하지 않는다.

## 1차 지원 범위 — 2026-11-25 확정

| 종류 | Master 관점 | 모델 연결 방향 |
| --- | --- | --- |
| DI | 디지털 입력 읽기 | 동작 모델 출력 → 어댑터 → 입력 프로세스 데이터 |
| DO | 디지털 출력 쓰기 | 출력 프로세스 데이터 → 어댑터 → 동작 모델 입력 |
| AI | 아날로그 입력 읽기 | 동작 모델 출력 → 어댑터 변환 → 입력 프로세스 데이터 |
| AO | 아날로그 출력 쓰기 | 출력 프로세스 데이터 → 어댑터 변환 → 동작 모델 입력 |

IO-Link는 1차 구현 범위에서 제외한다. 기본 검증 구성은 슬롯1 DI8(CPX-AP-I-8DI-M8-3P), 슬롯2 DO8(CPX-AP-I-8DO-M8-3P), 슬롯3 AI4/AO4(CPX-AP-I-4AI4AO-U-I-M12)로 확정했다. 모든 CPX 모듈 지원을 의미하지 않는다.

선정 AI/AO의 PDO는 ESI 기준 signed 16-bit little-endian raw 정수로 표현한다. 표현 범위 -32768..32767과 정상 신호 범위를 구분한다. 물리량 단위·변환·정상 신호 범위는 모델/채널 계약에서 정하며 32767=10V 같은 공통 가정은 두지 않는다. 범위 초과 설정·모델 변환값은 오류로 처리하고 자동 clamp하지 않는다. Loader의 디지털 사용 사례만으로 AI/AO 검증을 대신하지 않는다.

### AIO PDO 배치와 공급 전원 제어 — 2026-11-26 확정

CPX-AP-I-4AI4AO-U-I-M12의 RxPDO는 ESI의 9바이트 배치를 그대로 유지한다. 아래 offset은 station 전체가 아닌 해당 모듈 RxPDO 시작 기준이다.

| 위치 | 내용 | 크기 | 1차 처리 |
| --- | --- | --- | --- |
| byte 0~7 | AO 채널 0~3 | 각 signed Int16, 총 64bit | 채널별 raw 값을 연결 동작 모델에 전달 |
| byte 8 bit 0~3 | Supply output 0~3 | 4bit | 배치를 유지해 수신하되 공급 전원 동작은 모델링하지 않음 |
| byte 8 bit 4~7 | Padding | 4bit | 값으로 해석하거나 binding하지 않음 |

- 공급 출력 비트를 제거하여 RxPDO를 8바이트로 축소하거나 일반 DO 채널로 노출하지 않는다. 뒤에 오는 모듈의 offset도 전체 9바이트를 기준으로 계산한다.
- 공급 출력 비트는 모델 Enable·AO 차단·AI 값/유효성 변경 조건으로 사용하지 않는다. 0 또는 1 수신에 관계없이 기존 raw AO 전달과 모델 계산 조건을 유지한다.
- 공급 제어는 ESI 기본 Automatic에 대응하는 한정된 범위이며 실제 센서/액추에이터 전원·전압·전류·전원 고장·전원 차단 효과를 시뮬레이션하지 않는다. By process data 모드 설정 및 관련 장치 파라미터 쓰기는 기존 모듈 설정 제외 정책을 따른다.
- 공급 비트 값만으로 전원 이상 진단을 만들지 않는다. 모델 입력 station의 OP/출력 유효성 및 모델/Host 장애 정책은 별도로 유지한다.
- 이번 결정은 해당 AIO 모듈의 부가 공급 비트 처리이며 일반 DO 또는 다른 모듈의 전원 제어 의미로 확대하지 않는다.

## 확정한 구성·모델 연결

모듈은 [ADR-005](../Design/ADR-005-device-configuration.md)의 `DEVICE_SIMULATOR_IO_io0_MODULES=1:DI:8,2:DO:8,3:AIO:4:4` 문법을 사용한다. Motion Server parser/ESI와 Soft ESC parser/모듈 검증을 구현·확인했다. CPX 모듈 OD 간격은 ESI AP-Slot 기준 0x10이다. Motion Server의 MODULE_PDO_INDEX_STRIDE도 0x10으로 설정한다.

모델 인스턴스별 생성·채널별 명시적 연결·미연결 처리·오류 구분은 [ADR-007](../Design/ADR-007-cia402-profile-adapters.md)의 합의 원칙을 따른다. IO 하나에 여러 모델을 연결할 수 있다. 설정 키는 `DEVICE_SIMULATOR_IO_MODELS`와 `DEVICE_SIMULATOR_IO_<io_id>_BINDINGS`로 확정했다. 모델 선언은 `인스턴스 ID:프리셋 ID`, 연결은 `슬롯:종류:채널=ID.입출력명`이다. 실린더 동작은 아래의 검증된 공압 FMU 재사용 결정을 따른다. 이전 virtual_cylinder 예시가 실제 구현 모델 등록을 뜻하지 않는다. 아날로그 시험 모델은 아래 순수 지연 FMU 계약을 따르며 예시 loader0/analog0 등의 인스턴스 이름을 제품에 하드코딩하지 않는다. 기존 축의 AXIS_MODELS는 유지한다.

## 채널·모델 신호 1:1 연결 — 2026-11-26 확정

- IO 채널 하나와 모델 신호 하나의 1:1 binding만 지원한다. DO/AO는 모델 입력 하나, DI/AI는 모델 출력 하나에 연결한다.
- IO 채널의 식별 키는 `(io_id, 슬롯, 종류, 채널 번호)`, 모델 신호의 식별 키는 `(인스턴스 ID, 입출력명)`이다. 전체 IO binding 목록에서 두 키 각각의 중복을 시작 시 거부한다. 같은 연결 행의 중복도 거부한다.
- 한 DO/AO를 여러 모델 입력에 분배하거나 여러 DO/AO를 같은 모델 입력에 연결하지 않는다. 모델 출력 하나를 여러 DI/AI로 분배하거나 여러 모델 출력을 하나의 DI/AI로 합치지 않는다.
- 서로 다른 인스턴스의 같은 이름 신호는 별개다. 같은 프리셋을 여러 인스턴스가 사용하는 것은 허용하며 실행 상태와 연결은 독립적이다.
- 실린더 연결 대상은 `extend`, `retract` 입력과 `extended`, `retracted` 출력이다. 실린더 하나에 DO 2개와 DI 2개를 각각 독립적으로 연결한다.
- 실린더에는 AI/AO binding을 제공하지 않는다. 위치·속도·압력·힘이 FMU에 존재해도 IO 채널로 노출하지 않으며 이러한 아날로그 연결 설정은 지원하지 않는다.
- AI/AO 지원은 RF-013 범위에 유지하며 실린더와 별도로 순수 지연 FMU를 연결해 검증한다. AI/AO에도 1:1 규칙을 동일 적용한다.
- 기존 미연결 IO 채널 기본값 정책은 유지한다. 모델 입력의 필수 연결 여부는 모델 정의에서 명시하며, 실린더의 필수 입력은 아래 정책을 적용한다.

## 실린더 필수 입력 연결 — 2026-11-26 확정

| 입력 연결 상태 | 처리 |
| --- | --- |
| extend/retract 모두 연결 | 모든 입력 station의 OP·출력 유효성 및 시작/재개 조건을 만족하면 계산 |
| 하나만 연결 또는 모두 미연결 | 초기화만 수행하고 계산하지 않음 |

- 실린더의 extend와 retract는 모두 필수 연결이다. 미연결 입력을 OFF로 보충하여 계산하지 않는다.
- 연결 미완료는 모델 고장이 아닌 실행 대기 사유로 구분한다. 정상 계산 중이라고 표시하지 않는다. 초기화 결과는 기존 DI/AI 초기 상태 정책에 따라 제공하며 움직임을 계산하지 않는다.
- 유효한 구성에서 필수 입력 연결만 누락된 경우와, 존재하지 않는 신호/채널·잘못된 방향·중복 binding 등 잘못된 설정은 구분한다. 후자는 기존 시작 오류 정책을 유지한다.
- extended/retracted 출력 연결은 선택 사항이다. 입력 조건을 만족하면 출력 일부가 미연결이어도 계산하고 연결된 DI에만 결과를 전달한다.
- binding 설정 변경은 재시작 시 적용한다. 운전 중 자동 연결/재배선 기능은 추가하지 않는다.
- 다른 동작 모델은 해당 모델 정의에서 필수 입력을 명시한다. 필수 입력 집합이 없는 자율 모델의 시작 조건까지 이 실린더 정책으로 추정하지 않는다.


## 아날로그 순수 지연 FMU — 2026-11-26 동작·입출력 계약 확정, 제작 전

AO 입력을 지정한 시간만큼 지연한 뒤 같은 값으로 AI에 출력하는 별도 FMU를 사용한다. 1차 지연(목표값을 서서히 따라가는 응답)이나 디바운스가 아닌 순수 시간 지연이다. 실린더의 AI/AO 연결로 대신하지 않는다.

| 항목 | 계약 |
| --- | --- |
| 입력 | command, signed 16-bit 정수, AO 채널 하나와 연결 |
| 출력 | feedback, signed 16-bit 정수, AI 채널 하나와 연결 |
| 범위 | -32768..32767, 음수·0·최솟값·최댓값 보존 |
| 단위·변환 | 물리 단위 및 스케일 변환 없음. raw 정수를 그대로 전달 |
| 지연 설정 | 모델 프리셋의 동작 모델 설정으로 지정 |
| 초기 출력 | 지연된 입력 이력이 도달하기 전에는 0 |
| 계산 | 기존 IO 모델 8ms 단계·입력 스냅샷 계약 적용 |

### 지연 이력과 출력 시점

- 8ms 계산 입력 스냅샷을 모델 시간과 함께 보관하고 각 샘플을 지정한 지연 후 순서대로 출력한다. 새 입력이 들어와도 이전 샘플을 취소하거나 지연 타이머를 다시 시작하지 않는다.
- 지연은 모델 시뮬레이션 시간 기준이다. 실제 스케줄 지연을 FMU 지연값에 덧붙이거나 모델 시간을 따라잡기 위해 추가 진행하지 않는다.
- 지연 시간을 8ms 배수로 제한하지 않는다. 해당 샘플의 적용 모델 시간 + 지연 시간보다 이르지 않은 첫 계산 시점에 출력한다. 지연 20ms의 샘플은 24ms 계산 시점에 처음 관측된다.
- 지연 0은 같은 계산 단계에서 입력값을 출력한다. 미연결 IO의 자동 loopback이 아니라 명시적으로 연결한 지연 모델의 동작이다.
- 전체 입력 전이 이벤트가 아닌 8ms 스냅샷 이력을 보관한다. 두 스냅샷 사이에 사라진 펄스는 재현하지 않는다.
- 출력은 다음 지연 샘플이 도달할 때까지 직전 값을 유지한다. 아날로그 보간·평활화·clamp를 추가하지 않는다.

### 계산 단계와 시간 기준 — 2026-11-26 리뷰 반영

- 계산 시작 모델 시각을 t, 고정 단계 h를 0.008s로 둔다. 입력 스냅샷은 t에 적용한 샘플로 기록하며 doStep은 [t, t+h]를 진행한다. 입력 적용 시각을 계산 종료 시각으로 잘못 기록하지 않는다.
- 단계 종료 시각 t+h에서, 샘플 적용 시각 + delay_seconds가 t+h 이하인 가장 최근 샘플을 feedback으로 평가한다. 아직 도달한 샘플이 없으면 0을 출력한다. 성공한 단계의 결과만 게시한다.
- 0 지연은 해당 입력을 받은 같은 계산 요청의 완료 결과에 반영한다. 첫 단계 종료 시각이 8ms인 것은 계산/게시 단계이며 8ms 지연 버퍼를 추가한다는 뜻이 아니다. 초기화 직후 출력 0과 첫 계산 완료 결과를 구분한다.
- t=0에 입력한 샘플은 D=0에서 첫 요청 완료(모델 시각 8ms), D=16ms에서 모델 시각 16ms, D=20ms에서 모델 시각 24ms의 완료 결과에 처음 나타난다. 실제 PDO 관측 시각은 별도다.
- FMU 구현·실행기·시험 모두 위 경계를 사용한다. delay=0의 direct feedthrough를 이유로 계산 성공 전에 입력을 IO 결과로 먼저 게시하지 않는다.

지연 24ms 예시(입력은 단계 시작에 적용, 출력은 단계 완료 결과):

| 입력 적용 모델 시각 | 입력 command | 계산 종료 모델 시각 | 출력 feedback |
| --- | ---: | --- | ---: |
| 0ms | 100 | 8ms | 0 |
| 8ms | 200 | 16ms | 0 |
| 16ms | -100 | 24ms | 100 |
| 24ms | 300 | 32ms | 200 |
| 32ms | 400 | 40ms | -100 |

### 일시정지·복구와 범위

- 정상 버스 일시정지 시 모델 시간과 지연 버퍼를 함께 유지한다. 재개는 멈춘 모델 시간에서 이어간다. 실제 시간이 지났다는 이유로 버퍼를 소진하지 않는다.
- Simulator 재시작 시 버퍼를 비우고 출력 0부터 시작한다. 이전 운전 중 이력을 영구 저장/복원하지 않는다.
- 모델 계산 오류/Host 장애의 값 유지·진단·수동 재시작 정책은 공통 계약을 따른다. 고장 때 출력을 초기값 0으로 덮어쓰지 않는다.
- 인스턴스별 지연 버퍼·출력·시간은 독립적이며 채널/신호 전역 1:1 규칙을 적용한다.
- 연결 조건·설정은 아래 확정 계약을 따른다. FMU 제작 방식과 artifact는 구현 준비 단계에서 정한다.
- 이번 요청은 계약 문서화다. FMU 생성·코드 변경·빌드·운영 설정 적용은 수행하지 않는다. 일반 물리량 아날로그 모델의 스케일링 계약을 이 raw 시험 모델로 확정하지 않는다.

### 연결 조건·설정 형식 — 2026-11-26 확정

- 모델 등록명은 `analog_delay`다. `command`는 AO 하나에 연결하는 필수 입력이며 `feedback`은 AI 하나에 선택 연결한다. 전역 1:1 연결 규칙을 적용한다.
- command 미연결이면 초기화 후 출력 0으로 대기하며 모델 시간·버퍼를 진행하지 않는다. 연결 미완료 자체는 Fault가 아니다.
- command 연결 후 해당 입력 station의 OP·새 유효 출력 조건을 만족해야 계산한다. feedback 미연결이어도 계산할 수 있다. 다른 station의 AI로 결과를 전달할 수 있으며 출력 전용 station 이탈은 계산을 중단하지 않는다.
- 프리셋 `config.delay_seconds`는 초 단위 유한 숫자이며 기본값 0.016(16ms), 허용 범위는 0~10초(양 끝 포함)다. 생략 시 FMU 기본값도 0.016으로 일치시킨다.
- 음수·10초 초과·숫자가 아닌 값(불리언 포함)·NaN·무한대는 시작 오류로 처리한다. 잘못된 값의 자동 보정은 없다. 상한은 1차 버퍼 자원 범위를 제한하기 위한 계약이다.
- 초기 출력은 0으로 고정한다. 이 모델에는 별도 IO_MODEL_INSTANCES가 필요 없다. 프리셋 변경은 재시작 후 적용하며 버퍼는 초기화한다.
- 8ms 비배수 지연의 첫 허용 계산 시점 적용, 값 변환 없음, 일시정지 시 버퍼 유지 정책은 앞의 계약을 그대로 따른다.

프리셋 설계 예시: `model_presets/signal_processing/delay/analog_delay_16ms.json` (4단계에서 모델·FMU·프리셋 구현 완료).

```json
{
  "schema_version": 1,
  "id": "analog_delay_16ms",
  "model": "analog_delay",
  "config": {
    "delay_seconds": 0.016
  }
}
```

```ini
DEVICE_SIMULATOR_IO_MODELS=analog0:analog_delay_16ms
DEVICE_SIMULATOR_IO_io0_BINDINGS=3:AO:0=analog0.command
DEVICE_SIMULATOR_IO_io1_BINDINGS=3:AI:0=analog0.feedback
```

위 예시는 두 station의 슬롯 3에 해당 아날로그 채널이 구성돼 있다는 전제다. 실제 BUS/MODULES 설정과 함께 검증하며 같은 키에 기존 연결이 있으면 목록에 합쳐 선언한다.

## 여러 IO station에 걸친 모델 연결 — 2026-11-26 확정

- 모델 인스턴스 하나를 여러 IO station에 걸쳐 연결할 수 있다. 같은 station 안에 모든 IO를 두도록 제한하지 않는다. 채널/모델 신호의 전역 1:1 원칙은 유지한다.
- 예: io0의 DO→cylinder0.extend, io1의 DO→cylinder0.retract, io2의 DI←cylinder0.extended, io3의 DI←cylinder0.retracted. 각 IO 키에 실제 슬롯·채널을 지정한다.
- 입력 station 집합은 해당 모델의 입력에 DO/AO가 연결된 station들이다. 출력 station 집합은 모델 결과가 DI/AI로 연결된 station들이다. 같은 station이 두 집합에 속할 수 있다. 이 명칭은 모델 관점이며 EtherCAT Master의 IO 방향과 구분한다.
- 연결된 모든 입력 station이 OP이고 출력 데이터가 유효할 때 모델 계산을 허용한다. 입력 station 하나라도 조건을 잃으면 새 계산을 금지하고 아래 진행 중 1단계 처리 규칙을 거쳐 일시정지한다.
- 재개는 모든 입력 station의 조건 회복과 각 입력의 새 유효 데이터 확보 후 수행한다. 이전 세션의 입력만으로 먼저 계산하지 않으며 멈춘 실제 시간의 따라잡기 계산은 하지 않는다.
- DI/AI 결과만 받는 station의 통신 상실은 해당 모델의 계산 중단 사유가 아니다. 정상 입력 조건이면 모델 계산과 다른 정상 출력 station 갱신은 계속한다. 끊긴 경로로 결과 전달이 성공했다고 간주하지 않는다.
- 출력 전용 station이 복귀하면 해당 station의 입력 데이터 제공 가능 상태에 따라 최신 유효 모델 결과를 반영한다. 해당 station의 복귀만으로 모델을 초기화하거나 시간을 되돌리지 않는다.
- 입력과 출력을 모두 연결한 station은 입력 의존성 규칙을 적용한다. 물리 링크 상실이 여러 station의 입력 유효성을 함께 잃게 했다면 실제 영향받은 집합을 기준으로 일시정지한다.
- 모델 장애의 영향받는 station·모듈·채널은 내부 진단 상세정보로 기록하며 CPX 진단으로 투영하지 않는다. 정상 station의 연결되지 않은 다른 모델까지 계산 중단시키지 않는다. 공용 Host 장애 범위는 별도 기존 정책을 따른다.
- 여러 station 입력은 아래 입력 스냅샷 정책을 적용하고 IO 모델은 고정 8ms 주기로 계산한다. 서로 다른 프레임의 값이 동일 Master 주기에 속한다고 보장하지 않는다.

## 입력 스냅샷·IO 모델 고정 주기 — 2026-11-26 확정

- station별로 수신한 최신 유효 출력값과 유효성 정보를 보관한다. 모델 계산 시작 시 해당 모델이 사용하는 입력 전체를 하나의 일관된 스냅샷으로 복사한다.
- 모든 입력 station의 OP·출력 유효성 및 시작/재개 조건을 확인한 뒤 스냅샷을 적용한다. 계산 도중 새로 수신한 값은 현재 계산의 일부 입력에 끼워 넣지 않고 다음 계산에 사용한다.
- 모델당 한 계산 주기에 한 번 계산하고, 성공한 결과를 연결된 DI/AI 채널에 반영한다. 한 모델의 입력 station·binding 개수만큼 중복 계산하지 않는다. 실린더는 기존 결정대로 DO/DI만 연결한다.
- IO 모델 계산은 공통 실행부의 고정 8ms 주기를 사용한다. FMU 한 계산 단계의 시뮬레이션 시간 증가량은 0.008s다. EtherCAT 프레임 수신마다 계산하거나 station 수에 따라 모델 시간을 추가 진행시키지 않는다.
- EtherCAT IO 전송 주기와 동작 모델 계산 주기를 분리한다. 새 계산 결과가 없을 때 전송 계층은 기존 정책에 따라 마지막 값을 제공한다. 프레임 수신 경로를 매번 FMU 계산 완료 대기로 묶지 않는다.
- 스냅샷은 계산 중 입력 일관성을 보장하는 정책이다. 서로 다른 station 데이터가 동일 Master 주기에 생성/수신됐다는 보장은 아니다.
- 최신값 스냅샷 방식은 모든 입력 전이 이력을 보존하는 큐가 아니다. 두 스냅샷 사이에 ON/OFF가 모두 끝난 짧은 펄스는 모델에서 관측되지 않을 수 있다. 8ms 설정만으로 실제 시간 기준 펄스 포착이나 실시간 마감 준수를 보장하지 않는다.
- 고정 주기는 정상 실행의 목표이며 지연/초과는 아래 계산 지연 정책을 따른다. 이미 합의한 버스 일시정지 후 중단 시간 따라잡기 없음 정책도 유지한다.
- 이 정책은 Remote I/O 동작 모델 대상이다. 기존 CiA402 축의 계산 주기나 실행 경로는 자동 변경하지 않는다. 설정 키·IPC 세부 구현은 기존 분리 구조에 맞춰 구현 시 정한다.

### 계산 도중 입력 station 조건 상실 — 2026-11-26 리뷰 반영

- 입력 조건 상실을 감지하면 새 계산의 시작을 즉시 금지한다. 아직 시작하지 않은 요청은 진행하지 않는다. 이미 실행 중인 모델의 1단계만 완료를 기다린다.
- 진행 중 단계가 제한시간 이내 정상 완료하면 모델 시간·내부 상태와 해당 단계의 IO 결과를 함께 수락한 뒤 그 상태에서 일시정지한다. 내부적으로는 조건 상실 시점부터 대기 중임을 유지하며 계산 성공이 운전 재개를 뜻하지 않는다.
- FMU 내부 상태는 진행시켰는데 공개 결과만 버려 이전 상태처럼 보이게 하거나, 지원되지 않는 rollback을 시도하지 않는다. 따라서 조건 상실 감지 후 최대 한 단계(모델 시간 8ms)의 상태/결과 반영이 가능하다. 이는 실제 시간 8ms 이내 완료 보장이 아니다.
- 결과는 연결 채널의 최신 값으로 보관하되 단절된 station으로 전달 성공을 가정하지 않는다. 출력 경로가 살아 있으면 정상 전송 규칙에 따라 제공한다.
- 계산 실패/Host timeout이면 정상 완료 수락 대신 기존 장애 정책을 적용한다. timeout으로 장애 고정 후 늦은 응답은 반영하지 않는다.
- 재개는 진행 중 단계 처리 완료와 모든 입력 station의 조건 회복·새 유효 입력 확보 후에만 가능하다. 처리 중 일시적인 OP 복귀로 계산을 중첩하거나 오래된 입력을 재사용하지 않는다.

## 계산 지연·시간 처리 — 2026-11-26 확정

| 상황 | 처리 |
| --- | --- |
| 정상 계산 | 성공한 계산 단계마다 모델 시뮬레이션 시간 8ms 진행 |
| 일시적인 8ms 주기 초과 | 응답 제한시간 이내 정상 완료 결과를 반영하고 초과 시간·횟수 기록 |
| 놓친 계산 시점 | 계산 요청을 누적하지 않고 놓친 회차를 몰아서 실행하지 않음 |
| 응답 제한시간 초과 | 기존 Host 장애 정책 적용, 마지막 정상 IO 값/진단 유지, EtherCAT Slave 유지 |

- 실제 계산/스케줄 지연이 12ms라고 FMU doStep 간격을 12ms로 늘리지 않는다. 한 계산 단계는 0.008s로 유지한다.
- 같은 모델의 계산을 중첩 실행하지 않는다. 계산 중 놓친 실행 시점의 요청 큐를 만들지 않으며 후속 계산에는 그 시점의 최신 유효 입력 스냅샷을 적용한다.
- 8ms를 한 번 초과했다는 이유만으로 Fault를 발생시키지 않는다. 주기 초과와 응답 제한시간 초과를 별도 판단한다. 지속 초과에 대한 별도 Fault 기준은 이번 합의에 추가하지 않는다.
- 지연이 지속되면 모델 시뮬레이션 시간이 실제 시간보다 느려질 수 있다. 계산 시간·스케줄 지연·주기 초과 시간/횟수 및 모델 시간 지연을 계측한다. 명시적인 버스 일시정지 시간과 계산 지연을 구분하여 기록한다.
- 모델 계산이 성공했어도 이미 Host 응답 제한시간 초과로 장애가 고정된 세션을 늦은 응답으로 정상화하지 않는다. 기존 수동 Docker 재시작 복구 원칙을 유지한다.
- 기존 응답 제한시간 설정/Host 장애 경계를 재사용하며 타이머 기산점과 IPC 구현은 기존 코드와 대조한다. 이 문서에서 새로운 timeout 설정값을 임의 도입하지 않는다.
- 계측으로 확인하기 전 실제 8ms 마감 준수나 실시간 동기화를 보장하지 않는다. 기존 CiA402 축의 주기/오류 정책은 이 결정으로 변경하지 않는다.

## 기존 기반과 변경 지점

현재 설정/Host는 축 전용이다. CiA402 필수 Controlword/Statusword, AxisFault 투영과 공통 전송·검증을 분리한다. Remote I/O를 CiA402 하위 축으로 취급하지 않는다.

장치당 논리 OD 하나를 유지한다. PDO mapping/assignment는 Slave가 관리하고 동작 파라미터는 기능 모델 소유다. 모델 IPC에 매핑 절차를 추가하지 않는다. CPX는 아래 고정 PDO 계약을 적용하며 기존 RF-014의 축 동적 매핑·영구 저장 계약은 유지한다.

### CPX 고정 PDO·최소 설정 범위 — 2026-11-26 확정

- 시작 시 .env의 station별 모듈 종류·개수·순서와 선택 ESI로 고정 PDO 및 process image를 생성한다. 모듈 구성 변경은 정지·설정 수정·재시작·Master 재검색으로 적용한다.
- 해당 PDO mapping 객체와 0x1C12/0x1C13 assignment의 개수·항목은 개별 SDO 읽기를 지원한다. Motion Server가 실제 배치를 조회·검증할 수 있어야 한다.
- mapping/assignment 쓰기는 PRE-OP를 포함한 모든 상태에서 거부한다. clear/rewrite 또는 현재와 동일한 값 쓰기도 정상 SDO Abort로 응답하며 기존 매핑·Slave·Host를 유지한다. Complete Access 미지원 원칙도 유지한다.
- CPX 매핑은 별도 영구 저장/복원하지 않는다. 매번 모듈 구성에서 생성하며 .env에 별도 PDO 선택/매핑 설정을 추가하지 않는다. 기존 축 매핑 파일·저장 동작은 변경하지 않는다.
- 0xF030 모듈 목록 쓰기·조회·검증과 0xF050 조회는 유지한다. F030은 .env에 구성된 모듈과 기대 목록의 일치를 확인하는 기능이며 PDO 재매핑이나 가상 모듈 생성/삭제 수단이 아니다. 현재 서버의 항목 쓰기 → 개수 쓰기 → 재조회 순서를 지원한다.
- 1차 모듈 설정 최소 범위: 장치 식별·모듈 구성 확인·DI/DO/AI/AO 데이터 교환만 지원한다. DI debounce, DO fail-state, AI/AO 신호 범위·필터·스케일·출력 제한 설정과 AP 파라미터 접근·0x27F1 저장은 제외한다. 미지원 SDO 요청을 가짜 성공/기본값으로 응답하지 않는다.
- AI/AO raw Int16 전달, 버스 조건 상실 시 모델 일시정지·상태 유지, 동작 모델 프리셋 계약은 유지한다. CPX 전체 하드웨어 기능/ESI 파라미터를 구현했다고 선언하지 않는다.
- CPX는 기본 오류 상태 OD의 개별 SDO 읽기만 지원한다. 진단 PDO·진단 이력·Emergency 전송은 제외하며 진단 assignment 추가를 허용하지 않는다. 아래 진단 계약을 따른다.


자체 .env에 모듈/슬롯/채널 및 모델 연결 구성을 추가한다. 환경 변수 문법은 ADR-005의 채택 내용을 따르며, 동작 모델 입출력명은 아래 실린더/analog_delay 계약을 따른다. 모델 설정은 프리셋/IO_MODEL_INSTANCES로 관리하고 실행 상태를 저장하지 않으며 기존 축 저장 계약은 유지한다. Motion Server .env를 읽거나 Demo 전용 구성을 코드에 고정하지 않는다.

## 복동 실린더 FMU 재사용 — 2026-11-25 채택

직접 작성할 일정 속도 모델 대신 공개 PneumaticCircuits 부품을 조합한
`SoftESCDoubleActingCylinder` FMU를 IO 연결용 동작 모델로 사용한다. `loader0`는
인스턴스 예시이며 프로파일이나 동작 모델에 고정하지 않는다.

- 선택 산출물: Playground Export, FMI 3.0 Co-Simulation, solver `auto`, Linux x86-64.
- 보관: `model_artifacts/SoftESCDoubleActingCylinder-fmi3-web.fmu`. 파일 해시·환경·결과는
  [Linux 검증 보고서](../Validation/Pneumatic-Cylinder-Web-FMU-20261125.md)에 기록했다.
- 출처·고정 커밋·Modelica 소스·Export 방법: [모델 README](../../model_sources/pneumatic_cylinder/double_acting/README.md).
- Linux에서 100mm 왕복(8ms/1ms), 50mm 변경, 무공압, 명시적 이벤트 처리의 5개 시험을 통과했다.
  현재 사용 가능한 것은 동작 모델의 오프라인 실행이며 Soft ESC에 IO 모델로 등록된 상태는 아니다.

| 기존 binding 논리 신호 | FMU 변수 | 의미 |
| --- | --- | --- |
| extend | extend_command | 전진 파일럿 Boolean 입력 |
| retract | retract_command | 후진 파일럿 Boolean 입력 |
| extended | extended_sensor | 전진 끝단 Boolean 출력 |
| retracted | retracted_sensor | 후진 끝단 Boolean 출력 |

이 대응은 어댑터 구현에 적용할 연결 계약이며 binding 파서가 현재 지원한다는 뜻은 아니다.
FMU는 위치(m), 속도(m/s), 절대압(Pa), 공압력(N)도 제공하지만, 실린더의 IO binding은 DO/DI로 한정한다. 이 값을 AI로 노출하지 않고 실린더에 AO도 연결하지 않는다. AI/AO 모델 연결·변환·검증은 별도 대상으로 유지한다.

동작 모델은 3/2 파일럿 밸브·5/2 메모리 밸브·복동 실린더를 포함한다. **두 입력 OFF는
정지가 아니라 밸브 방향 유지**다. 움직임은 공압·부하·기구 파라미터에 따라 계산한다.
초기 위치는 기본 0m, 스트로크 100mm, 공급압 6bar(gauge), 센서 폭 1mm다. 끝단은
탄성 접촉이어서 작은 위치 초과가 가능하다. `opposing_force`는 고정 파라미터이며
동적으로 변화하는 외력 입력은 아니다. 제조사 정밀 모델이나 실제 장비 정확도 보증은 아니다.

이 결정은 앞서 논의한 `virtual_cylinder`의 OFF/OFF 정지·전진/후진 각 1초·일정 속도
구현 계획을 대체한다. 그 이전 계약은 작업 일지에 이력으로 보존한다. 두 입력 ON은
원본 밸브의 압력/이력에 따르며 정상 시험 명령으로 사용하지 않았다. 두 입력은 모두 ON인 경우까지 그대로 FMU에 전달한다. 상충 명령 판단·진단·인터록은
상위 애플리케이션 책임이며 어댑터에 추가하지 않는다. FMU 호출 실패·자료형 불일치 등
실행/연결 오류 처리는 별개로 유지한다. FMU에 없는 정지/Reset 기능을
구현된 것으로 간주하지 않는다.

일반 Co-Simulation(eventModeUsed=false, earlyReturnAllowed=false)을 사용한 8ms
직접 호출이 통과했다. 명시적 Event Mode를 쓰려면 Boolean 입력 갱신 시 Event Mode
전환과 Early Return을 처리해야 한다. Windows에서 따로 만든 FMI 2.0 FMU의
0.1ms 세분화 조건을 이 FMI 3.0 산출물에 그대로 적용하지 않는다.

## 2026-11-26 — 동작 모델 설정 구분과 개선 분리

- 장치 파라미터(OD/SDO)와 동작 모델 설정을 구분한다. 스트로크·직경·이동 질량·센서 감지 폭 및 정격 유량은 동작 모델 설정이다.
- 공급압·외력은 외부 운전 조건, 초기 위치는 초기 조건이다. 현재 FMU에서는 이 값들을 parameter로 노출한다. XML의 tunable 표시만으로 실행 중 변경 검증이 완료됐다고 보지 않는다.
- 위치·속도·챔버 압력은 상태이며 센서·공압력은 계산 출력이다. 실제 질량 유량은 내부 계산 결과이며 외부 입출력으로 노출되지 않는다.
- 정격 유량 외부 설정 지원은 [RF-021](RF-021-pneumatic-cylinder-fmu-improvements.md)로 분리했다. 현재 IO 연결은 기존 검증 FMU 그대로 진행하며 재Export를 기다리지 않는다.
- 동작 모델 특성은 모델 프리셋 JSON, 인스턴스별 운전 조건·초기 조건은 `.env`의 IO_MODEL_INSTANCES로 분리한다. 이전 전체 `.env`/세 그룹 제안을 대체하며 `state`에 중복 저장하지 않는다.

## 동작 모델 실행 구성 관리 — 2026-11-26 확정

- `model_presets/`의 JSON은 재사용할 모델 종류·특성을 보관한다. `.env`는 프리셋 선택·인스턴스별 운전 조건/초기 조건·IO 연결을 보관한다. 기존 축 OD 저장 계약은 유지한다.
- 선언한 값을 FMU 초기화 완료 전에 FMI에서 허용하는 단계에 적용한다. 생략한 항목은 선택한 FMU의 기본값을 사용한다. 어댑터가 임의의 다른 기본값으로 덮어쓰지 않는다.
- 지원하지 않는 항목·잘못된 값은 시작 시 오류로 처리한다. 형식/범위/항목 간 관계를 검사하며 입력을 조용히 무시하거나 clamp하지 않는다.
- 설정 변경은 Simulator 재시작 시 적용한다. 운전 중 설정 변경·저장 API는 이번 구현에 추가하지 않는다.
- 재시작 시 선언한 초기 조건과 나머지 FMU 기본 초기 조건을 사용한다. 종료 직전 위치·속도·압력·밸브 상태를 자동 복원하지 않는다.
- 전진·후진 명령은 IO binding으로 전달한다. 현재 FMU의 공급압·외력은 `.env`의 고정 운전 조건으로 초기화하며 시간 변화 입력으로 취급하지 않는다.
- 이 관리 원칙의 합의가 Remote I/O 구현·검증 완료를 뜻하지 않는다.

## 프리셋·인스턴스 설정 문법 — 2026-11-26 채택·구현

모델 선언은 `인스턴스 ID:프리셋 ID`다. 이전 `ID:모델 종류` 제안을 대체한다. 프리셋의 `model`이 동작 모델 종류를 지정한다. 같은 프리셋으로 만든 인스턴스의 FMU·실행 상태는 각각 독립적이다. 기존 AXIS_MODELS는 변경하지 않는다.

기본 프리셋: [cylinder_100mm.json](../../model_presets/pneumatic_cylinder/double_acting/cylinder_100mm.json).

```json
{
  "schema_version": 1,
  "id": "cylinder_100mm",
  "model": "pneumatic_double_acting",
  "config": {
    "stroke": 0.100,
    "piston_diameter": 0.020,
    "rod_diameter": 0.008,
    "moving_mass": 0.15,
    "sensor_width": 0.001
  }
}
```

```ini
DEVICE_SIMULATOR_IO_MODELS=cylinder0:cylinder_100mm,cylinder1:cylinder_100mm

# 운전 조건·초기 조건 통합: Pa(gauge), N, m
DEVICE_SIMULATOR_IO_MODEL_INSTANCES=cylinder0: supply_gauge_pressure:600000,opposing_force:0,initial_position:0

# 슬롯 1=DI8, 슬롯 2=DO8인 io0에 연결하는 예
DEVICE_SIMULATOR_IO_io0_BINDINGS=2:DO:0=cylinder0.extend,2:DO:1=cylinder0.retract,1:DI:0=cylinder0.retracted,1:DI:1=cylinder0.extended
```

- 프리셋 JSON에는 `schema_version`, `id`, `model`, `config`를 둔다. 운전 조건·초기 조건은 넣지 않는다. 프리셋은 Git 관리 대상이며 실행 중 수정/자동 저장하지 않는다.
- `.env`의 IO_MODEL_INSTANCES는 `인스턴스:항목:값,항목:값,다음인스턴스:항목:값` 목록이다. 세 부분 항목은 새 인스턴스 그룹을 시작하고 두 부분 항목은 현재 그룹에 속한다. 항목과 인스턴스 그룹 모두 쉼표로 구분하며 기존 줄 연속 표기를 지원한다. CONFIG/CONDITIONS/INITIAL 개별 키는 채택하지 않는다.
- 실린더 IO_MODEL_INSTANCES의 항목은 supply_gauge_pressure, opposing_force, initial_position이다. 프리셋의 스트로크·직경 등을 `.env`에서 덮어쓰지 않는다. 다른 모델 특성이 필요하면 다른 프리셋을 만든다.
- 단위는 m, kg, Pa, N이다. 공급압은 게이지압, 챔버 출력은 절대압이다. 값에 단위 문자열을 붙이지 않는다.
- 인스턴스 설정 전체나 개별 항목을 생략하면 해당 FMU 기본값을 사용한다. 프리셋 config에서 생략한 설정도 FMU 기본값을 사용한다. 초기화 완료 전에 FMI에서 허용하는 단계에 두 종류의 설정을 적용한다.
- 누락/중복 프리셋 ID, 미지원 schema/model, 미선언 인스턴스 설정, 중복/미지원 항목 및 잘못된 값은 시작 오류로 처리한다. 모델 정의의 허용 항목·범위·관계 조건을 검사한다.
- 프리셋 및 IO_MODEL_INSTANCES 변경은 재시작 시 적용한다. 종료 직전 실행 상태를 자동 복원하지 않는다.
- 인스턴스 ID는 영문자/숫자로 시작하는 1~64자의 영문/숫자/밑줄/하이픈 이름이며 모델 인스턴스 사이에서 유일해야 한다. 프리셋은 model_presets 아래 JSON의 id로 탐색하고 중복을 거부한다. 모델별 artifact 파일명은 어댑터 등록표로 선택하며 실린더는 검증한 웹 Export 원본을 사용한다.
- 정격 유량 설정은 RF-021 후속이다. 현재 프리셋에 미지원 항목을 추가하지 않는다.
- 4단계에서 로더·모델 등록·Docker 반영을 완료했다. `.env.example`과 tests/fixtures/cpx-fmu.env에 실행 구성을 제공한다.

## EtherCAT 상태와 동작 모델 계산 — 2026-11-26 확정

Remote I/O에 연결된 동작 모델의 계산 수명주기는 공통 모델 실행부에서 관리한다. 어댑터의 명령 상충 판단이나 동작 모델에 없는 정지 명령으로 구현하지 않는다. 기존 축 실행 정책을 이 결정만으로 변경하지 않는다.

| 상황 | 모델 입력 처리 | 모델 계산 |
| --- | --- | --- |
| Simulator 시작 | 명령 입력 OFF 및 지정한 초기 조건 적용 | 초기화만 수행 |
| 입력 station 중 하나 이상 PRE-OP / SAFE-OP | 수신 DO/AO로 모델을 진행시키지 않음 | 계산 정지 상태 유지 |
| 모든 입력 station OP 및 유효 출력 확보 | 각 입력의 첫 유효 출력 데이터 적용 | 계산 시작 |
| 모든 입력 station 조건 정상 | 유효 수신 출력 적용 | 계속 계산 |
| 입력 station의 OP 이탈 / 통신 상실 감지 | 마지막 입력 보관, 새 계산 금지 | 진행 중 1단계 정상 완료 반영 후 일시정지. 실패/timeout은 장애 정책 |
| 모든 입력 station 조건 회복 | 각 입력의 새 유효 출력 데이터 적용 | 보관한 상태에서 계산 재개 |
| 출력 전용 DI/AI station 이탈 | 모델 입력 조건은 유지 | 계산 계속, 해당 전달 경로는 불가 |
| Simulator 재시작 | 초기 조건 재적용 | 종료 직전 실행 상태는 복원하지 않음 |

- 일시정지는 시뮬레이션 시간의 진행을 멈추는 것이다. 실린더에 정지 명령을 생성하거나 전진·후진 입력을 자동 OFF하지 않는다. 현재 메모리 밸브는 두 입력 OFF만으로 실린더 정지를 보장하지 않는다.
- PRE-OP/SAFE-OP가 재진입한 상태라면 보관한 모델 상태를 유지한다. 매 상태 전이마다 모델을 재생성하거나 초기 위치로 돌리지 않는다.
- OP 플래그만으로 계산을 재개하지 않는다. 상태/유효성 조건을 만족하는 새 출력 데이터가 필요하며 이전 세션의 오래된 명령으로 먼저 계산하지 않는다.
- 재개 시 일시정지한 실제 경과 시간을 누적하여 몰아서 계산하지 않는다. 모델 시간은 멈춘 지점에서 이어간다.
- 통신 상실은 단순히 한 주기 프레임이 늦었다는 이유로 판단하지 않는다. Slave 상태·출력 데이터 유효성·watchdog 판정을 근거로 한다. 구체적인 검출 신호·watchdog 설정/검증은 구현 설계에서 대조한다.
- 이 표는 버스 상태에 따른 정상 일시정지/재개 정책이다. FMU 실행 실패·Host 장애를 OP 재진입만으로 자동 복구하는 정책이 아니다.
- 일시정지/실행 실패 때 DI/AI 값 유지와 상태 구분은 아래 정책으로 확정한다. 모델 상태·유효성은 내부에서 관리하며 CPX 진단 OD/PDO로 전달하지 않는다. 외부 상태 전달은 후속 별도 경로의 책임이다.

## DI/AI 값·유효성 처리 — 2026-11-26 확정

| 상황 | DI/AI 값 | 상태 처리 |
| --- | --- | --- |
| 초기화 완료·계산 시작 전 | 초기화 결과 | 초기 상태 |
| 정상 계산 | 최신 계산 결과 | 정상 |
| 입력 station 조건에 따른 모델 일시정지 | 진행 중 단계가 정상 완료하면 그 결과까지 반영한 뒤 유지 | 일시정지; 자체 Fault 아님 |
| 출력 전용 station의 전달 경로 상실 | 모델 내부 결과는 계속 갱신 | 해당 경로의 전달 불가와 모델 계산 상태를 구분 |
| FMU 계산 실패·Host 장애 | 마지막 정상 계산값 유지 | 갱신 불가·오류 상태 |
| 정상 재개 | 새 계산이 성공한 뒤 갱신 | 정상 전환 |

- DI 전체 OFF 또는 AI=0을 장애 대체값으로 만들지 않는다. 값 보관과 유효성/진단을 구분한다. 미연결 채널의 기본값 정책과 연결된 모델의 오류 처리는 별개다.
- 초기화 실패는 시작 오류다. 정상 계산값이 없는 상태를 마지막 정상값처럼 제시하지 않는다.
- 정상 재개는 허용된 재개/복구 후 새 계산 성공을 뜻한다. Host Fault를 OP 재진입만으로 자동 해제한다는 뜻은 아니다.
- 모델 오류의 내부 진단은 기존 Diagnostic 데이터 구조를 재사용한다. 상충 명령 판단은 기존 합의대로 상위 애플리케이션 책임이다.

## 동작 모델 장애 영향 범위·복구 — 2026-11-26 확정

| 상황 | 영향 범위 | 처리 |
| --- | --- | --- |
| 특정 FMU의 계산 오류·잘못된 출력 | 해당 모델과 연결된 IO 채널 | 해당 모델 계산 중단, 마지막 정상값 유지, 내부 진단 발생 |
| 다른 모델은 정상 | 해당 정상 모델의 채널 | 계산·IO 갱신 계속 |
| 공용 모델 프로세스 종료·응답 지연 | 해당 프로세스가 담당하는 모든 모델 | 마지막 정상값 유지, 내부 Host 장애 진단 |
| 장애 후 복구 | 현재는 Simulator 전체 | 사용자가 Docker를 재시작하여 초기 조건부터 시작 |

- EtherCAT Slave는 유지한다. 모델 프로세스와 Slave의 분리만으로 검증이 완료된 것으로 보지 않으며 오류/종료/지연 시험으로 확인한다.
- 모델별 계산 실패는 해당 모델에 고정하고 후속 주기에 자동 재시도하거나 OP 재진입만으로 해제하지 않는다. 정상 모델의 갱신은 계속한다.
- 버스 상태에 따른 정상 일시정지는 새 유효 출력으로 자동 재개한다. 모델 계산 오류·Host 장애는 이 경로와 구분하며 수동 재시작이 필요하다.
- 공용 프로세스에서 한 FMU의 무한 대기·네이티브 충돌이 발생하면 해당 프로세스 내 다른 모델도 영향을 받을 수 있다. 이 경우 개별 모델 격리 성공으로 간주하지 않고 Host 공통 장애를 적용한다. RF-018의 기존 축 Host 장애 경계를 유지한다.
- 모델 오류는 내부 Diagnostic에 원인·모델 ID·복구 필요 여부를 기록한다. Host 오류는 Host 전체 범위로 식별한다. station/모듈/채널 목록은 중복 기록하지 않으며 필요시 binding 설정에서 연결 관계를 확인한다. 모델 ID/Host 범위는 채널 하드웨어 오류 분류를 뜻하지 않는다. CPX Category·오류 수·latest-module/code·Error register·진단 이력·Emergency에는 모델 오류를 반영하지 않는다.
- 잘못된 출력은 해당 모델의 유효한 새 출력으로 게시하지 않는다. 기존 값 유지/유효성 정책을 적용한다.
- 초기화 실패는 시작 오류이며 이번 운전 중 장애 격리 정책으로 무시하지 않는다.
- 모델 단독 재생성·관리 API·자동 복구는 이번 범위에 추가하지 않는다. 수동 재시작은 지정한 초기 조건을 적용하며 마지막 운전 상태를 복원하지 않는다.

## 모델 내부 진단과 CPX 장치 진단 분리 — 2026-11-26 확정

- 동작 모델 계산 실패·잘못된 출력·모델 Host 종료/IPC timeout은 내부 Diagnostic과 로그로 검출·기록한다. 모델 오류를 CPX Software/Misc/채널 오류로 분류하거나 외부 CPX 진단 코드로 할당하지 않는다. 앞선 Misc 매핑 논의는 이번 결정으로 대체한다.
- 해당 모델 계산 중단·마지막 정상 DI/AI 유지·정상 모델 계속 실행·Host 장애 영향 범위·EtherCAT Slave 유지·수동 Docker 재시작 복구 정책은 유지한다. 진단 전달 제외가 장애 검출이나 격리 제외를 뜻하지 않는다.
- Host 종료/응답 지연은 살아 있는 Slave 측 감시 경로에서 내부 진단을 남길 수 있어야 한다. 종료된 Host가 자체 보고한다고 가정하지 않는다.
- CPX 진단은 CPX 자체의 장치·모듈 구성·지원 파라미터·통신 진단에 한정한다. 모델 오류만으로 0x1001, 0x6102, 모듈 진단 영역, 0x10F3 또는 Emergency를 변경하지 않는다. 별개로 실제 CPX/통신 오류가 검출되면 해당 장치 계약에 따라 처리한다.
- 2026-11-26 재확인: DO 명령 이후 DI 센서 도달 여부·동작 완료 제한시간 등 공정/장치 동작의 타임아웃 판단은 상위 애플리케이션 책임이다. Soft ESC는 이를 감시하거나 CPX 모듈 오류로 생성하지 않는다. FMU 계산 실패/응답 제한시간은 별개의 내부 실행 보호·진단이며 CPX로 전달하지 않는다. 내부 진단에는 모델 ID 또는 Host 범위·복구 필요 여부만 요구하고 연결 station/모듈/채널 목록은 요구하지 않는다.
- CPX 기본 오류 상태 OD 읽기만 1차 지원한다. 오류 요약 0x1001 및 현재 진단 요약 0x6102를 기준으로 개별 SDO 읽기·형식·지원 장치 상태 대응을 구현 지원표에 명시한다. 동작 모델의 정상 여부를 나타내는 필드로 사용하지 않는다.
- 진단 PDO(0x1AF1 및 0x1AF0), 진단 이력(0x10F3), Emergency 전송은 1차 범위에서 제외한다. 자동/선택형 진단 PDO 추가, 이력 저장·조회·acknowledge, Emergency 활성화 기능을 구현하지 않는다. 미지원 SDO 요청은 정상 Abort로 응답한다.
- 기본 오류 상태 OD는 읽기 전용이며 실제 지원·검출하는 CPX 자체 상태만 표현한다. 모델 오류를 합산하거나 미구현 하드웨어 진단을 가장하지 않는다. SDO Abort 및 EtherCAT AL 상태/상태 코드는 기존 프로토콜 경로로 처리하며 모든 요청 실패를 새 CPX 진단 사건으로 만들지 않는다.
- 내부 모델 진단·로그는 계속 유지한다. CPX 진단 이력 제외가 내부 오류 기록 삭제를 뜻하지 않는다. 모델 오류용 Category/진단 코드 조사는 더 이상 미결 항목이 아니다.
- 정상 WKC/OP·CPX 진단 정상·보관된 DI/AI 값만으로 동작 모델 계산 정상 여부를 알 수 없다. 별도 전달 경로가 마련되기 전에는 내부 상태/로그로 확인한다.
- 향후 Omniverse 등 상위 애플리케이션은 별도 경로로 모델 상태·유효성을 수집하고 표시·대응한다. Soft ESC는 DT에 독립적이며 이번 RF에서 Omniverse 연동·관리 API·별도 통신 프로토콜을 구현하지 않는다. 기존 CiA402 축 Fault/Reset 계약도 변경하지 않는다.
- [CPX ESI·서버 경로 조사](../Validation/CPX-Diagnostic-Path-20261126.md)의 기술적 근거는 유지하되 모델 오류를 CPX로 전달하던 제안은 철회했다. Motion Server의 CPX 자체 진단 수집/표시는 별도 작업이며 모델 진단 전달의 대체 경로가 아니다.
- 0x27F1 저장 API 의미 정합성은 사용자 등록 Motion Server **TD-044**(`docs/tasks/td/TD-044-cpx-parameter-storage-semantics.md`)로 추적한다. 이 저장소에서 Motion Server를 수정하지 않는다.

- 모델 오류는 내부 진단·값 유지·장애 격리와 CPX 진단에 미반영됨을 검증한다. CPX 자체 진단은 확정한 OD 지원 범위에서 별도로 검증한다. Motion Server/Omniverse의 외부 진단 수집·표시는 이번 모델 장애 검증의 선행 조건이 아니다.

- 항목별 수행 결과는 아래 완료 기준/5단계 기록을 따른다. 아날로그 raw·지연·독립성은 기존 자동 시험을 수용하고 수동/물리 FMU 왕복은 사용자 결정으로 생략했다. 임의의 장시간 시험 시간이나 모든 주기의 8ms 마감 준수를 새 합격 조건으로 추가하지 않는다.

## 구현 준비 항목과 진행 추적 — 2026-11-26

### 추가 합의 필요 여부

기존 필수 범위 합의와 리뷰 보완을 모두 반영했다. AIO는 9바이트 PDO를 유지하고 공급 전원 제어는 모델링하지 않기로 확정했으며 구현 착수 전에 남은 필수 사용자 결정은 없다. 고정 PDO·최소 모듈 설정 범위·기본 오류 상태 OD 읽기와 진단 PDO/이력/Emergency 제외까지 확정했다. 아래는 구현 설계·근거 확인 작업이며 새로운 제품 정책 질문으로 되돌리지 않는다. 실제 코드/ESI 대조에서 합의와 양립할 수 없는 요구가 발견된 경우에만 해당 차이를 제시한다.

### 추가 제품 정책 질문보다 구현 준비·근거 확인으로 처리할 항목

- 선택 CPX ESI Identity/revision, 모듈 식별/순서, 초기화 OD·SDO, 기본 오류 상태 OD의 자료형/정상값/실제 검출 상태, PDO offset/정렬 및 오류 응답 요구를 표로 고정한다. CPX는 고정 매핑 읽기/쓰기 거부/시작 시 생성으로 구현하고 RF-014의 축 동적 매핑·저장을 회귀한다.
- Slave의 출력 갱신/유효성·AL 상태·watchdog 검출을 기존 KickCAT 코드와 대조한다. 여러 station의 입력 스냅샷과 일시정지/재개 판정 경계를 구현 설계로 구체화한다.
- 공통 FMI 실행기는 현재 생성자에서 초기화까지 끝내므로 프리셋/IO_MODEL_INSTANCES와 초기 명령을 초기화 완료 전에 전달하는 경로를 추가한다. FMI 변수별 허용 설정 단계와 초기 출력 읽기를 검증하고 기존 Copley 초기화 동작을 회귀한다.
- 공통 비동기 IO 계산과 기존 축 실행·IPC timeout 경계를 대조한다. 8ms 계산과 프레임 처리 분리 및 Host 종료 후 내부 진단 유지 경로를 확인한다.
- 프리셋 ID 탐색·중복 검사·인스턴스 ID 문법, 모델 등록명/검증된 artifact 선택·Docker/배포 포함을 기존 구조에 맞춰 명세한다. 운영 .env/기존 축 저장을 임의 이관하지 않는다.
- 아날로그 지연 FMU 제작 방법은 공통 실행기와 Int16 계약을 만족하는 재현 가능한 방식으로 조사한다. FMI 3.0 Co-Simulation/Linux x86-64를 우선 검토하되 4단계에서 C99 기반 FMI 3.0 Co-Simulation/Linux x86-64 FMU로 구현했다. 정수 이력 버퍼를 FMU 내부에 두며 Python 대체 계산을 사용하지 않는다.
- 1차 fixture·오프라인 참조 결과·물리 시험 절차를 준비한다. 이전 실린더 오프라인 검증을 IO 전체 구현 완료로 확대하지 않는다.

주요 연결·실행·지연·장애·복구 정책과 1차 검증 구성은 확정했다. 위 목록은 추가 정책 결정이 아니라 구현 준비·근거 확인 작업이다. 항목별 현재 구현·검증 상태는 아래 단계표와 완료 기준을 따른다. 전체 물리 통합 시험 완료를 뜻하지 않는다.

## 5단계 최종 결과 및 완료 판정 — 2026-11-26

- 사용자 확인: Motion Server 버스 연결·초기화 완료, 실린더 수동 테스트 완료. 해당 동작을 다시 시험해야 한다는 의미로 미완료 처리하지 않는다.
- 사용자 결정: 아날로그 수동 시험 생략. 실제 지연 FMU의 Int16 값/경계·지연·독립성·분산 연결·일시정지·재시작 자동 시험을 수용한다. Panel AO UI 추가나 물리 AO→FMU→AI 왕복을 이 RF의 완료 선행 조건으로 두지 않는다.
- 위 결정은 실제 물리 아날로그 경로 검증 완료를 뜻하지 않으며 최종 검증 범위에 한계로 명시한다.

자동 검증 근거 보완(기존 4번)은 세 묶음 시험을 수행해 완료했다. IO 단위/실제 FMU 35개, 전체 단위 88개 통과(1개 환경 생략), Docker 실제 FMU 12개, KickCAT 두 구성의 mailbox/OP/WKC 시험이 통과했다. [자동 경계 시험 결과](../Validation/RF-013-boundaries-20261126.md)를 참조한다.

혼합 운전·계측(기존 1번)도 완료했다. 60.531초 동안 가상축 4개·실린더 2개가 각각 15회 왕복했고 WKC 조회 1,171회 모두 24/24, Fault/IPC 오류 관측 0이었다. 설정 주기 4ms, 수신 간격 최대 10.036ms(8ms 초과 2건)를 기록했다. 모든 프레임 WKC 캡처나 RT 성능 보증은 아니다. [혼합 운전 결과](../Validation/RF-013-mixed-operation-20261126.md).

Host 장애·복구(기존 2번)도 완료했다. SIGSTOP/SIGKILL 각각 약 5초 동안 97회 WKC 표본 모두 24/24, 마지막 IO·SDO·Slave 유지 및 수동 재시작/초기 조건 복원을 확인했다. 재연결 시 실제 축 통신 오류 0x8188은 Reset으로 해제했다. [장애·복구 결과](../Validation/RF-013-host-recovery-20261126.md).

CPX 재구성·재검색(기존 3번)도 완료했다. io1 슬롯4 DO8 추가로 출력 10→11바이트·F030/F050/assignment·새 DO PDO/SDO 값을 확인하고 원래 구성으로 복원했다. 변경 구성 WKC 조회 69회 모두 24/24. [재구성·원복 결과](../Validation/RF-013-reconfiguration-20261126.md).

합의 범위 미완료 항목 없음. RF-013을 완료로 판정한다. 아날로그 물리 전체 왕복 생략·최소 CPX 지원 범위·비RT 검증 한계는 그대로 유지한다. 후속 기능을 이 RF의 완료 조건에 추가하지 않는다. [5단계 종합 기록](../Validation/RF-013-stage5-20261126.md).

## 제외·후속 및 근거

IO-Link, IODD/ISDU, 범용 센서 라이브러리, 제조사 실측 기반의 정밀 공압 모델 개발·정량 검증은 이번 구현에 포함하지 않는다. 선택한 공개 FMU가 제공하는 압력·부하 계산은 재사용한다. DI/DO/AI/AO는 모두 1차 구현 범위다. Modular Device Profile 전체 및 모든 CPX 모듈의 적합성을 선언하지 않고 구현한 범위를 명시한다.

RF-005의 실제 CPX 통신 및 RF-011/014/018의 축 검증은 기반 근거이며 가상 Remote I/O 구현 완료를 대신하지 않는다. 해당 RF 완료 상태는 유지한다. 외부 DT/Sync·Pairing·ROS2·Omniverse 구현은 이 RF의 범위가 아니다.

## IO 설정 키 정리 — 2026-11-26

- DEVICE_SIMULATOR_IO_MODELS: 인스턴스 이름과 프리셋 ID 목록. 기존 BEHAVIOUR_MODELS 대체.
- DEVICE_SIMULATOR_IO_MODEL_INSTANCES: 각 인스턴스의 운전 조건·초기 조건을 모은 단일 목록. 기존 MODEL_<id>_INSTANCE_CONFIG 대체.
- 인스턴스 선언·설정·IO binding의 역할과 내부 동작 모델 계약은 동일하다. 키 이름 변경만으로 모델을 새로 만들거나 저장 파일을 이관하지 않는다.
- 미선언/중복 인스턴스 설정, 중복 항목, 구분자 누락, 비유한 숫자·미지원 항목·범위 밖 값은 설정 오류다. 기존 키가 남으면 명시적 오류를 반환한다. 지연 FMU는 인스턴스 설정 없이 프리셋의 delay_seconds를 사용한다.

```ini
DEVICE_SIMULATOR_IO_MODELS=\
    cylinder0:cylinder_100mm,\
    cylinder1:cylinder_100mm,\
    analog0:analog_delay_16ms,\
    analog1:analog_delay_16ms

# Per-instance operating and initial conditions; use commas between instance groups.
DEVICE_SIMULATOR_IO_MODEL_INSTANCES=\
    cylinder0: supply_gauge_pressure:600000,initial_position:0,\
    cylinder1: supply_gauge_pressure:600000,initial_position:0
```

그룹 간 쉼표를 생략하지 않는다. 설정 전체/개별 값 생략 시 FMU 기본값을 쓰며 초기화 전에 적용하는 정책은 유지한다.

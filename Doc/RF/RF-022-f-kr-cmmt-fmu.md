# RF-022 — F-KR CMMT 동작 모델 FMU 전환

- 현재 상태: **예정**
- 상태 상세: 2026-11-26 사용자 동의로 등록. 드라이브 운전 로직을 포함한 독립 동작 모델의 FMU 전환. 구현·Export·시험 미착수.
- 등록일: 2026-11-26
- 연계: [RF-015](RF-015-axis-model-semantics.md), [RF-016](RF-016-cia402-profile-adapter.md), [RF-017](RF-017-copley-fmu.md), [RF-018](RF-018-diagnostic-fault.md)

## 목적과 합의한 책임 경계

기존 F-KR CMMT 동작 모델을 FMU로 제공하여 Soft ESC 밖에서도 재사용하고, Soft ESC에서는 Copley와 같이 FMI 실행기를 통해 호출한다. 위치 계산뿐 아니라 드라이브 운전 상태·명령 처리·움직임 계산·장치 제한·Fault 동작을 포함한다. 실제 CMMT 전체 사양이나 물리적 정확도를 보증하는 의미가 아니다.

| 구성 | 책임 |
| --- | --- |
| EtherCAT Slave | EtherCAT·Mailbox·SDO/PDO 통신, 기존 Slave 측 매핑 처리 |
| CiA402 Drive 프로파일·OD 및 F-KR CMMT 어댑터 | 장치 OD와 FMU 변수 변환, 지원 객체·명령 검증과 통신 오류 응답 |
| F-KR CMMT FMU | 드라이브 운전 상태, 합의한 PP/PV/Jog/Homing 동작, 위치·속도 계산, 장치 제한·Fault |
| 기존 Soft ESC 저장소 | 파라미터 파일 저장·복원. FMU에 저장 경로나 EtherCAT 매핑을 넘기지 않음 |
| 기능 모델 프로세스·FMI 실행기 | 생성·초기화·시간 진행·종료, 기존 장애 격리와 연결 |

EtherCAT Slave와 기능 모델 프로세스의 분리는 유지한다. FMU는 기능 모델 프로세스에서 라이브러리로 호출하며 FMU 전용 IPC 프로세스를 추가하지 않는다. 외부 OD와 FMU 내부 계산 상태는 구분하고 동일 장치에 두 개의 독립적인 공개 OD를 만들지 않는다.

현재 F-KR 구현은 OD 직접 접근과 어댑터의 모델 내부 상태 접근이 있으므로 그대로 포장하는 것만으로 경계 분리가 완료되지 않는다. FMI 입력·출력·설정·상태 전환 계약을 명시하고 직접 접근을 대체한다.

## RF-015와의 분담 및 초기 권장 순서

RF-015는 동작의 의미와 합격 기준을, RF-022는 FMU 경계·산출물·실행 연결·전환 동등성을 담당한다. 두 RF의 완료를 서로 선행 조건으로 요구하지 않는다.

2026-11-26 후속 정리: 현재 작업은 RF-015의 정책 통합·코드 대조와 그에 따른 구현이다. 아래 FMU 우선 전환 순서는 최초 제안으로 보존하며 RF-015 구현의 필수 선행 조건이 아니다. 이 RF는 예정 상태를 유지하고 별도 착수 시 기존 구현/검증 결과를 바탕으로 순서를 갱신한다.

1. RF-015 선행 설계: 현행 명령/OD/PDO 대조, 위치 제한·정지·재개·Homing·파라미터 반영 정책과 시험 기준 확정. 현재 결과와 원하는 결과를 구분한다.
2. RF-022 계약 및 기준 확보: FMU 변수·자료형·단위·갱신 시점·초기화·시간 진행을 정의하고 기존 Python 모델의 입력 시퀀스와 기준 결과를 확보한다.
3. RF-022 전환: 동작 변경을 최소화해 FMU를 제작하고 기존 모델과 비교한다. 알려진 부족분은 RF-015 개선 대상으로 유지한다.
4. RF-015 개선: 확정 정책의 부족분을 FMU에서 보완한다. 의도한 동작 변경과 전환으로 생긴 차이를 분리한다.
5. 통합 검증: FMI 연결, 기존 파라미터·PDO 매핑·장애 격리 회귀, F-KR 다축 및 Copley/IO 혼합 검증. 보고서를 공유하되 각 RF의 완료 기준을 별도로 판정한다.

RF-015 전체를 Python 모델에서 먼저 완료한 뒤 같은 개선을 다시 이식하는 방식은 권장하지 않는다. 동작 기준 없이 FMU 전환과 의미 변경을 동시에 수행하지 않는다. 이 순서는 권장 계획이며 구현 착수를 의미하지 않는다.

## 구현 전에 확정할 사항

- Co-Simulation을 기본 방향으로 한다. FMI 버전과 Export 도구는 기존 실행기 호환성을 대조한 뒤 확정한다.
- 기존 Python 재사용 또는 다른 언어 이식 여부를 런타임 의존성·다중 인스턴스·배포성 기준으로 선택한다. Modelica 재작성은 필수 조건이 아니다.
- Controlword/Statusword 등 원시 변수 또는 의미 기반 명령의 노출 방식, 단위 변환 책임, FMI 변수 목록과 오류 표현.
- 명령·운전 중 설정 변경의 갱신 시점, 초기 조건, Fault Reset과 모델 재생성의 차이.
- 외부 통신 간격과 내부 계산 간격, 허용 시간 간격·계산 지연, 수치 비교 허용오차.
- 기존 지원 CSP/회전 동작의 전환 범위·보존 방법. RF-015의 CSP/회전 확장 제외를 기존 기능의 묵시적 삭제로 해석하지 않는다.
- 모델 식별자·저장 파일 호환성·교체 절차. 이름이나 저장 스키마는 이 등록만으로 변경하지 않는다.

## 제외 범위

Copley 운전 모드 확장, 실제 CMMT 전체 사양 재현, 새로운 모터 전기·토크·외력 물리 모델, 외부 DT/Omniverse 통합은 자동 포함하지 않는다. FMU 패키징만으로 모델 정확도나 계산 성능이 개선된 것으로 간주하지 않는다.

## 2026-11-26 — RF-015 단위 계약 연결

[RF-015](RF-015-axis-model-semantics.md)의 단위 변환 합의를 적용한다. EtherCAT OD의 원시값/단위 설정은 유지하고 F-KR 어댑터에서 변환한다. FMU는 위치 m·속도 m/s·가감속 m/s²·시간 s를 사용하며 Controlword/Statusword/Mode는 정수·비트로 유지한다. FMU가 OD 주소나 CMMT 전용 변환 지수를 직접 읽지 않고 추가 counts_per_unit 설정을 만들지 않는다. 구체 변수 계약과 기존 기능 보존은 구현 설계에서 대조한다.
